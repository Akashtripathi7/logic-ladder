## module: mt09 | Binary numbers and bits
summary: Counting with only 0 and 1, place values 1, 2, 4, 8…, converting to and from binary, and the bit operations & | ^ << >>.
=== en
### The big idea
Computers store everything with switches that are either **off (0)** or **on (1)**. Binary is simply counting with those two digits. Each switch is a **bit**, and each place is worth **double** the one to its right.

### Place values: 1, 2, 4, 8
In base 10 the places are worth 1, 10, 100, 1000. In binary (base 2) they are worth **1, 2, 4, 8, 16, 32…**, doubling each time.

> **Analogy:** A row of light switches. Each switch has a price tag: 8, 4, 2, 1. To show a number, switch on the tags that add up to it. 13 = 8 + 4 + 1, so the switches read **1101**.

| 8 | 4 | 2 | 1 | value |
|---|---|---|---|---|
| 0 | 1 | 0 | 1 | 4 + 1 = 5 |
| 1 | 1 | 0 | 1 | 8 + 4 + 1 = 13 |
| 1 | 1 | 1 | 1 | 15 |

### Counting in binary
0, 1, 10, 11, 100, 101, 110, 111, 1000… The rightmost bit flips **every** step; the next flips every 2 steps; the next every 4. When all bits are 1 (like 111 = 7), adding one rolls over to 1000 = 8, just like 999 + 1 = 1000 in decimal.

### Decimal to binary
Keep dividing by 2 and collect the remainders (this is the digit loop from topic 5, with 2 instead of 10):
- 13 % 2 = 1, 13 // 2 = 6
- 6 % 2 = 0, 6 // 2 = 3
- 3 % 2 = 1, 3 // 2 = 1
- 1 % 2 = 1, 1 // 2 = 0 → stop

Read the remainders **bottom to top**: **1101**. In Python: `bin(13)` gives `'0b1101'`, and `int('1101', 2)` gives 13.

### Bit operations
Python can work on all the bits of a number at once:

| Operator | Name | Rule for each pair of bits | Example (12 = 1100, 10 = 1010) |
|---|---|---|---|
| `&` | AND | 1 only if **both** are 1 | 12 & 10 = 1000 = 8 |
| `\|` | OR | 1 if **either** is 1 | 12 \| 10 = 1110 = 14 |
| `^` | XOR | 1 if they are **different** | 12 ^ 10 = 0110 = 6 |
| `<<` | shift left | move bits left, double per step | 3 << 2 = 12 |
| `>>` | shift right | move bits right, halve per step | 12 >> 2 = 3 |

Two facts you will use again and again:
- `n & 1` is the **last bit**: 1 for odd, 0 for even (the same as `n % 2`).
- `x ^ x` is **0**, and `x ^ 0` is **x**. So XOR-ing a list where everything appears twice except one number leaves only that number.

> **Mistake:** `^` is XOR, not a power. `2 ^ 3` is 1, not 8. Powers use `**`.

### Where this shows up in DSA
- Single Number (XOR cancels pairs), Number of 1 Bits, Counting Bits, Reverse Bits, Missing Number.
- Subsets as bitmasks: with n items, the numbers 0 to 2ⁿ − 1 describe every subset.

> **Remember:** Binary places are 1, 2, 4, 8… `n & 1` is the last bit. `x ^ x == 0`. Shifting left doubles, right halves.

- `n & 1` **aakhri bit** hai: odd ke liye 1, even ke liye 0 (`n % 2` jaisa hi).
- `x ^ x` = **0**, aur `x ^ 0` = **x**. Toh aisi list ko XOR karo jismein ek number chhod ke sab do baar aate hain, toh sirf wahi number bachta hai.

## module: mt10 | Patterns and sums
summary: Spotting patterns in sequences, adding 1 to n with Gauss's trick, running totals, prefix sums and range sums.
=== en
### The big idea
Many problems are really **patterns**. Once you spot the rule, you can often replace a long loop with one small formula, or reuse work you have already done instead of repeating it.

### Spotting a pattern
- 3, 6, 9, 12, … adds **3** each time. The k-th term (starting at k = 1) is `3 * k`.
- 5, 8, 11, 14, … starts at 5 and adds 3: the k-th term is `5 + 3 * (k - 1)`.
- 1, 2, 4, 8, 16, … **doubles** each time: the k-th term is `2 ** (k - 1)`.
- 1, 4, 9, 16, 25, … are the **squares**: `k * k`.

> **Tip:** When a sequence confuses you, write the **differences** between neighbours. Constant differences mean "add the same amount each time".

### Adding 1 to n: Gauss's trick
The story goes that a young Carl Friedrich Gauss was told to add 1 + 2 + … + 100. He paired the numbers from both ends:
- 1 + 100 = 101, 2 + 99 = 101, 3 + 98 = 101 … all 50 pairs make 101.
- 50 × 101 = **5,050**.

The general formula: **1 + 2 + … + n = n × (n + 1) / 2**. In Python use `n * (n + 1) // 2` to stay with whole numbers.

> **Analogy:** Build a staircase of blocks: 1 block, then 2, then 3, up to n. Make a copy, turn it upside down and push the two together. You get a neat rectangle n wide and n + 1 tall. The staircase is exactly half of it.

You will meet this number constantly: it is also the number of **pairs** in a list (topic 11) and the work done by two nested loops.

### Running totals and prefix sums
A **running total** adds as it goes:

| day | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| sales | 3 | 1 | 4 | 1 | 5 |
| total so far | 3 | 4 | 8 | 9 | 14 |

Store those totals in a list called a **prefix sum**, with a 0 in front:
```python
nums = [3, 1, 4, 1, 5]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
# prefix == [0, 3, 4, 8, 9, 14]
```
Now the sum of any stretch is **one subtraction**. The sum of `nums[1..3]` (1 + 4 + 1) is `prefix[4] - prefix[1]` = 9 − 3 = **6**.

> **Analogy:** A car's odometer. To know how far you drove between 2 pm and 5 pm, you do not re-drive the road: you subtract the 2 pm reading from the 5 pm reading.

### Where this shows up in DSA
- Missing Number: the expected sum `n * (n + 1) // 2` minus the actual sum.
- Range sum queries, Subarray Sum Equals K, Product of Array Except Self (the same idea with multiplication).

> **Remember:** 1 + … + n = n(n + 1)/2. A prefix sum turns "add up a stretch" into one subtraction.

## module: mt11 | Counting: pairs, subsets and arrangements
summary: The multiplication rule, how many pairs, how many subsets, how many orders, and how counting predicts how slow a solution is.
=== en
### The big idea
Before writing a solution, good programmers **count how many possibilities there are**. That number tells you whether trying them all is fine or hopeless. Four small rules cover almost everything.

### Rule 1: multiply the choices
You have 3 shirts and 2 pairs of trousers. How many outfits? For **each** shirt there are 2 trousers: 3 × 2 = **6**.

> **Analogy:** A restaurant combo: pick 1 of 4 burgers, 1 of 3 drinks, 1 of 2 desserts. 4 × 3 × 2 = 24 different combos. Each independent choice multiplies.

In code, this is **nested loops**: an outer loop over shirts and an inner loop over trousers runs 3 × 2 = 6 times.

### Rule 2: pairs
5 friends, and everyone shakes hands with everyone else once. How many handshakes?
- Each person shakes 4 hands: 5 × 4 = 20. But that counts A–B and B–A separately, so halve it: **10**.

The number of pairs from n items is **n × (n − 1) / 2**. For n = 1,000 that is almost half a million pairs. This is why "check every pair" is slow for big inputs.

```python
for i in range(n):
    for j in range(i + 1, n):   # j starts after i: each pair once
        ...
```

### Rule 3: subsets (take it or leave it)
Pizza with 3 possible toppings: cheese, olives, corn. How many different pizzas, including a plain one? For each topping you decide **yes or no**: 2 × 2 × 2 = **8**.

With n items there are **2ⁿ subsets**. That doubles with every extra item: 10 items give 1,024 subsets, 20 give about a million, 40 give about a trillion.

### Rule 4: arrangements (order matters)
In how many orders can 4 runners finish a race? The winner can be any of 4, second place any of the remaining 3, then 2, then 1: 4 × 3 × 2 × 1 = **24**. This is **4 factorial**, written 4!.

Factorials explode even faster than powers: 10! is 3,628,800.

| Question | Count | n = 10 |
|---|---|---|
| Independent choices a and b | a × b | — |
| Pairs | n(n − 1)/2 | 45 |
| Subsets | 2ⁿ | 1,024 |
| Orders | n! | 3,628,800 |

### Where this shows up in DSA
- Nested loops cost n²; Subsets costs 2ⁿ; Permutations cost n!.
- Constraints warn you: if n can be 20, 2ⁿ is fine; if n can be 100,000, even n² is too slow.

> **Remember:** Independent choices multiply. Pairs: n(n − 1)/2. Subsets: 2ⁿ. Orders: n!.

## module: mt12 | Ranges, rounding and off-by-one
summary: Counting the numbers from a to b, inclusive and exclusive ends, the fence-post mistake, Python's range and slices, floor and ceiling.
=== en
### The big idea
"How many numbers from 3 to 7?" Many people say 4. The answer is **5**: 3, 4, 5, 6, 7. Being off by exactly one is the **most common bug in all of programming**, and it has a name: the **off-by-one error**.

### Counting a range
- From a to b, **both included**: **b − a + 1** numbers. 3 to 7 → 7 − 3 + 1 = 5.
- From a up to b, **b not included**: **b − a** numbers. 3 up to 7 → 4 numbers (3, 4, 5, 6).

> **Analogy:** The fence-post problem. A fence 10 metres long with a post every metre needs **11 posts**, not 10: one at the start plus one at the end of every metre. Gaps and posts differ by one.

### Python's range stops early
`range(a, b)` gives a, a + 1, …, **b − 1**. The stop value is **never included**. That is why:
- `range(5)` is 0, 1, 2, 3, 4: five numbers, and it matches the indexes of a list of length 5.
- To include b, write `range(a, b + 1)`.

Slices follow the same rule: `s[2:5]` takes indexes 2, 3, 4.

> **Tip:** Before running a loop, say its **first** and **last** value out loud. For `range(1, n)`, the last value is n − 1. If you wanted n, you need `range(1, n + 1)`.

### Indexes of a list
A list of length n has indexes **0 to n − 1**. The last item is `a[n - 1]` (or `a[-1]`). Asking for `a[n]` crashes with `IndexError`. When comparing each item with the next one, loop to `n - 1` so that `i + 1` still exists:
```python
for i in range(len(a) - 1):
    if a[i] > a[i + 1]:
        ...
```

### Overlapping ranges
Two meetings [1, 5] and [4, 8] overlap because each starts **before the other ends**: `start1 <= end2 and start2 <= end1`. Whether touching ends count as overlapping ([1, 5] and [5, 9]) depends on the problem; read it carefully.

### Rounding: floor and ceiling
- **Floor** rounds **down**: floor(3.7) = 3. Python: `math.floor(3.7)` or `7 // 2` for whole numbers.
- **Ceiling** rounds **up**: ceil(3.2) = 4. Python: `math.ceil(3.2)`, or `(a + b - 1) // b` for whole numbers (topic 3).
- `round(2.5)` in Python gives 2 (it rounds halves to the even number), so do not rely on it for "always up".

### Where this shows up in DSA
- Binary search boundaries (`lo <= hi` vs `lo < hi`, `mid + 1`, `mid - 1`).
- Sliding window lengths (`right - left + 1`), Merge Intervals, Meeting Rooms.

> **Remember:** a to b inclusive has b − a + 1 numbers. `range(a, b)` stops before b. A list of length n ends at index n − 1.

=== hi
### Bada idea
"3 se 7 tak kitne numbers?" Bahut log 4 kehte hain. Jawab **5** hai: 3, 4, 5, 6, 7. Theek ek se galat hona **programming ka sabse common bug** hai, aur iska naam hai **off-by-one error**.

### Range ginna
- a se b, **dono shaamil**: **b − a + 1** numbers. 3 se 7 → 7 − 3 + 1 = 5.
- a se b tak, **b shaamil nahi**: **b − a** numbers. 3 se 7 tak → 4 numbers (3, 4, 5, 6).

> **Analogy:** Fence-post problem. 10 metre lambi baad mein har metre pe khamba ho toh **11 khambe** chahiye, 10 nahi: ek shuru mein plus har metre ke end pe ek. Gaps aur khambe ek se alag hote hain.

### Python ka range pehle ruk jaata hai
`range(a, b)` deta hai a, a + 1, …, **b − 1**. Stop value **kabhi shaamil nahi**. Isliye:
- `range(5)` = 0, 1, 2, 3, 4: paanch numbers, aur ye 5 length wali list ke indexes se match karta hai.
- b shaamil karna hai toh `range(a, b + 1)` likho.

Slices bhi yahi rule follow karte hain: `s[2:5]` indexes 2, 3, 4 leta hai.

> **Tip:** Loop chalane se pehle uski **pehli** aur **aakhri** value zor se bolo. `range(1, n)` ki aakhri value n − 1 hai. n chahiye tha toh `range(1, n + 1)` chahiye.

### List ke indexes
n length wali list ke indexes **0 se n − 1** hain. Aakhri item `a[n - 1]` (ya `a[-1]`). `a[n]` maangoge toh `IndexError` crash. Har item ko agle se compare karte waqt `n - 1` tak loop chalao taaki `i + 1` bhi maujood ho:
```python
for i in range(len(a) - 1):
    if a[i] > a[i + 1]:
        ...
```

### Overlap karti ranges
Do meetings [1, 5] aur [4, 8] overlap karti hain kyunki har ek doosri ke **khatam hone se pehle** shuru hoti hai: `start1 <= end2 and start2 <= end1`. Chhoote hue ends ([1, 5] aur [5, 9]) overlap gine jaayein ya nahi, ye problem pe depend karta hai; dhyaan se padho.

### Rounding: floor aur ceiling
- **Floor** **neeche** round karta hai: floor(3.7) = 3. Python: `math.floor(3.7)`, ya whole numbers ke liye `7 // 2`.
- **Ceiling** **upar** round karta hai: ceil(3.2) = 4. Python: `math.ceil(3.2)`, ya whole numbers ke liye `(a + b - 1) // b` (topic 3).
- Python mein `round(2.5)` 2 deta hai (aadhe ko even number ki taraf round karta hai), toh "hamesha upar" ke liye iske bharose mat raho.

### DSA mein kahan aata hai
- Binary search ki boundaries (`lo <= hi` vs `lo < hi`, `mid + 1`, `mid - 1`).
- Sliding window ki length (`right - left + 1`), Merge Intervals, Meeting Rooms.

> **Yaad rakho:** a se b inclusive mein b − a + 1 numbers. `range(a, b)` b se pehle rukta hai. n length ki list index n − 1 pe khatam hoti hai.
