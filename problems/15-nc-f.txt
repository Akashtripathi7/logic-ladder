### maximum-subarray
title: Maximum Subarray
lc: 53 maximum-subarray
diff: Medium
pattern: Kadane's algorithm
problem: Largest sum of a contiguous (non-empty) subarray.
example: [-2, 1, -3, 4, -1, 2, 1, -5, 4] → 6 ([4, -1, 2, 1])
analogy: Carrying a backpack of past days' profits: if the backpack's total ever goes negative, it's only dragging you down, so drop it and start fresh today.
hints:
- Walk left to right keeping the best sum of a subarray ENDING here.
- If the running sum is negative, it can only hurt: start fresh at the current number.
- Track the best seen.
brute: For each start, extend and track sums: O(n²).
brutecx: O(n²)
signal: "Max sum of a contiguous subarray" → **Kadane: cur = max(x, cur + x)**.
optimal:
- cur = best = nums[0]; for x in nums[1:]: cur = max(x, cur + x); best = max(best, cur).
cx: O(n) time · O(1) space
code:
def max_sub_array(nums):
    cur = best = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best
test:
check(max_sub_array([-2, 1, -3, 4, -1, 2, 1, -5, 4]), 6)
check(max_sub_array([-3, -1, -2]), -1)
trace:
x | cur | best
−2 | −2 | −2
1 | 1 | 1
−3 | −2 | 1
4 | 4 | 4
−1 | 3 | 4
2 | 5 | 5
1 | 6 | 6
−5 | 1 | 6
4 | 5 | 6
mistakes:
- Starting best at 0 (wrong when all numbers are negative).
hinglish:
## Sawaal
Lagatar subarray ka sabse bada sum.
## Analogy
Pichhle dinon ke profit ka bag uthaye chal rahe ho: agar bag ka total kabhi negative ho jaaye toh wo sirf bojh hai, phenko aur aaj se naya shuru karo.
## Kaise sochein
- Yahan khatam hone wale subarray ka best sum rakho.
- Running sum negative → naye se shuru.
## Pattern pehchano
Max contiguous sum → Kadane.
## Galtiyan
best = 0 se shuru.

### jump-game
title: Jump Game
lc: 55 jump-game
diff: Medium
pattern: Greedy: farthest reach
problem: nums[i] is the max jump from i. Starting at 0, can you reach the last index?
example: [2, 3, 1, 1, 4] → True;   [3, 2, 1, 0, 4] → False
analogy: Crossing a river on stones where each stone says how far you can jump. Keep a marker at the farthest stone you could possibly reach so far; if you ever stand past that marker, you're stuck.
hints:
- Keep reach = farthest index reachable so far.
- Walk i; if i > reach → stuck → False.
- Else reach = max(reach, i + nums[i]).
brute: DP/DFS from each index: O(n²).
brutecx: O(n²)
signal: "Can I reach…" with jump ranges → **greedy farthest reach**.
optimal:
- reach = 0; for i, x: if i > reach → False; reach = max(reach, i + x). True.
cx: O(n)
code:
def can_jump(nums):
    reach = 0
    for i, x in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + x)
    return True
test:
check(can_jump([2, 3, 1, 1, 4]), True)
check(can_jump([3, 2, 1, 0, 4]), False)
check(can_jump([0]), True)
mistakes:
- Always taking the maximum jump (can overshoot a better route).
hinglish:
## Sawaal
nums[i] = i se maximum jump. 0 se aakhri index tak pahunch sakte ho?
## Analogy
Nadi ke pathar jahan har pathar batata hai kitna jump kar sakte ho. Ab tak ke sabse door pahunchne layak pathar pe marker rakho; kabhi marker se aage khade ho gaye toh atak gaye.
## Kaise sochein
- reach = ab tak ka sabse door index.
- i > reach → False; warna reach update.
## Pattern pehchano
Jump ranges se reachability → greedy farthest reach.

### jump-game-ii
title: Jump Game II
lc: 45 jump-game-ii
diff: Medium
pattern: Greedy BFS by jump levels
problem: The end is reachable; return the minimum number of jumps.
example: [2, 3, 1, 1, 4] → 2
analogy: Bus zones: from your current zone, look at every stop you can reach and find the farthest place the NEXT bus can take you. Each zone change is one jump.
hints:
- Think in BFS levels: indexes reachable with 1 jump, then 2 …
- The current level is a window [.., cur_end]; the next ends at the farthest i + nums[i] inside it.
- Count windows until the end is covered.
brute: DP min jumps: O(n²).
brutecx: O(n²)
signal: "Minimum jumps" → **BFS levels as index windows**.
optimal:
- jumps = cur_end = farthest = 0; for i in 0..n−2: farthest = max(...); if i == cur_end: jumps += 1; cur_end = farthest.
cx: O(n)
code:
def jump(nums):
    jumps = cur_end = farthest = 0
    for i in range(len(nums) - 1):
        farthest = max(farthest, i + nums[i])
        if i == cur_end:
            jumps += 1
            cur_end = farthest
    return jumps
test:
check(jump([2, 3, 1, 1, 4]), 2)
check(jump([2, 3, 0, 1, 4]), 2)
check(jump([0]), 0)
mistakes:
- Looping to the last index (counts an extra jump).
hinglish:
## Sawaal
End tak pahunchne ke minimum jumps.
## Analogy
Bus zones: apne zone ke har stop se dekho agla bus sabse door kahan le ja sakti hai. Har zone change ek jump.
## Kaise sochein
- BFS levels socho: 1 jump se pahunchne wale, phir 2…
- Current level ek window; agli window uske andar ke sabse door i + nums[i] tak.
## Pattern pehchano
Minimum jumps → windows wala BFS.
## Galtiyan
Aakhri index tak loop.

### gas-station
title: Gas Station
lc: 134 gas-station
diff: Medium
pattern: Greedy: reset the start when the tank goes negative
problem: gas[i] added at station i; cost[i] to reach the next. Return the start index for a full circle, or −1.
example: gas [1,2,3,4,5], cost [3,4,5,1,2] → 3
analogy: A road trip around a ring road: if you run dry between A and B, then starting anywhere from A to B wouldn't help either (you'd arrive with even less fuel). So the next possible start is just after B.
hints:
- Total gas < total cost → impossible.
- Otherwise walk once with a tank; tank < 0 at i → no start from the current start to i works; start at i + 1.
- The last start chosen is the answer.
brute: Try every start: O(n²).
brutecx: O(n²)
signal: Circular route with a running balance → **greedy reset + total check**.
optimal:
- total, tank, start; for i: diff; add to both; tank < 0 → start = i + 1, tank = 0. Return start if total ≥ 0 else −1.
cx: O(n)
code:
def can_complete_circuit(gas, cost):
    total = tank = start = 0
    for i in range(len(gas)):
        diff = gas[i] - cost[i]
        total += diff
        tank += diff
        if tank < 0:
            start, tank = i + 1, 0
    return start if total >= 0 else -1
test:
check(can_complete_circuit([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]), 3)
check(can_complete_circuit([2, 3, 4], [3, 4, 3]), -1)
mistakes:
- Skipping the total check.
hinglish:
## Sawaal
Gol raaste pe gas stations; kahan se shuru karein ki poora chakkar lage? Na ho toh −1.
## Analogy
Ring road trip: agar A aur B ke beech petrol khatam ho gaya, toh A se B ke beech kahin se bhi shuru karna bekaar (aur kam petrol ke saath pahunchoge). Agla possible start B ke theek baad.
## Kaise sochein
- Total gas < total cost → impossible.
- Ek pass: tank < 0 at i → start = i + 1.
## Pattern pehchano
Circular route + balance → greedy reset + total check.

### hand-of-straights
title: Hand of Straights
lc: 846 hand-of-straights
diff: Medium
pattern: Greedy from the smallest card + counts
problem: Can the cards be split into groups of groupSize consecutive values?
example: [1,2,3,6,2,3,4,7,8], 3 → True
analogy: Arranging students into relay teams of consecutive roll numbers: the smallest roll number left MUST start a team, because nobody smaller can come before them.
hints:
- The smallest remaining card must start a group.
- Take x, x + 1, …, x + size − 1 from the counts.
- Anything missing → False.
brute: Try all groupings.
brutecx: exponential
signal: Consecutive groups → **greedy from the smallest using counts**.
optimal:
- count = Counter(hand); for x in sorted(count): while count[x] > 0: for k in range(size): if count[x + k] == 0 → False; count[x + k] −= 1.
cx: O(n log n)
code:
from collections import Counter

def is_n_straight_hand(hand, size):
    if len(hand) % size:
        return False
    count = Counter(hand)
    for x in sorted(count):
        while count[x] > 0:
            for k in range(size):
                if count[x + k] == 0:
                    return False
                count[x + k] -= 1
    return True

- Starting groups from arbitrary cards instead of the smallest.

## Sawaal

## Analogy
Students ko lagatar roll numbers wali relay teams mein baantna: bacha hua sabse chhota roll number team ZAROOR shuru karega, kyunki usse chhota koi pehle aa hi nahi sakta.
## Kaise sochein
- Sabse chhota bacha card group shuru karega.
- x, x + 1, … counts se lo; kuch missing → False.
## Pattern pehchano

### merge-triplets-to-form-target-triplet
title: Merge Triplets to Form Target
lc: 1899 merge-triplets-to-form-target-triplet
diff: Medium
pattern: Greedy filtering
problem: Merging takes the max per position. Can you reach exactly target?
example: [[2,5,3],[1,8,4],[1,7,5]], target [2,7,5] → True
analogy: Mixing paint colours where each mix keeps the strongest shade per channel: any paint with even one channel too strong would ruin the mix, so throw those away and check whether the rest cover every target channel.
hints:
- A triplet with any value above target can never be used (max only grows).
- All other triplets are safe to merge.
- Check each target position is matched by some safe triplet.
brute: Try all subsets.
brutecx: O(2ⁿ)
signal: "Combine with max" → **discard overshoots, check coverage**.
optimal:
- found = set(); for t: skip if any t[i] > target[i]; add i where t[i] == target[i]. len(found) == 3.
cx: O(n)
code:
def merge_triplets(triplets, target):
    found = set()
    for t in triplets:
        if all(t[i] <= target[i] for i in range(3)):
            found |= {i for i in range(3) if t[i] == target[i]}
    return len(found) == 3

### partition-labels
title: Partition Labels
lc: 763 partition-labels
diff: Medium
pattern: Last occurrence + stretching window
problem: Split the string into as many parts as possible so each letter appears in at most one part. Return part sizes.
example: "ababcbacadefegdehijhklij" → [9, 7, 8]
analogy: Packing a wardrobe into boxes where all clothes of one colour must go in the same box: a box can only be closed once you've passed the LAST item of every colour already inside it.
hints:
- Record the last index of each letter.
- Walk; extend the current part's end to the last occurrence of each letter seen.
- When i reaches end, close the part.
brute: For each prefix, check whether any letter appears later: O(n²).
brutecx: O(n²)
signal: "Each item in one group only" → **last occurrence + stretching end**.
optimal:
- last = {ch: i}; start = end = 0; for i, ch: end = max(end, last[ch]); if i == end: record; start = i + 1.
cx: O(n)
code:
def partition_labels(s):
    last = {ch: i for i, ch in enumerate(s)}
    res, start, end = [], 0, 0
    for i, ch in enumerate(s):
        end = max(end, last[ch])
        if i == end:
            res.append(end - start + 1)
            start = i + 1
    return res

Almari ke kapde boxes mein pack karna jahan ek rang ke saare kapde ek hi box mein jaane chahiye: box tabhi band ho sakta hai jab andar rakhe har rang ka AAKHRI kapda paar ho chuka ho.

### valid-parenthesis-string
title: Valid Parenthesis String
lc: 678 valid-parenthesis-string
diff: Medium
pattern: Greedy range of possible open counts
problem: '(' ')' and '*' where '*' can be '(', ')' or empty. Can it be valid?
example: "(*))" → True;   ")(" → False
analogy: Counting guests in a room with some "maybe" guests who may enter, leave or do nothing: track the lowest and highest possible headcount. If even the highest goes negative, it's impossible; at the end the lowest must be able to be zero.
hints:
- Without '*' you'd track the open count.
- With '*', the open count could be a RANGE [lo, hi].
- '(' → both +1; ')' → both −1; '*' → lo −1, hi +1.
- hi < 0 → False. Keep lo ≥ 0. End: lo == 0.
brute: Try all 3^k choices.
brutecx: O(3^k·n)
signal: Wildcards with an open count → **track min and max balance**.
optimal:
- As in the hints.
cx: O(n)
code:
def check_valid_string(s):
    lo = hi = 0
    for ch in s:
        if ch == "(":
            lo += 1; hi += 1
        elif ch == ")":
            lo -= 1; hi -= 1
        else:
            lo -= 1; hi += 1
        if hi < 0:
            return False
        lo = max(lo, 0)
    return lo == 0
test:

check(check_valid_string("(*)"), True)
check(check_valid_string("(*))"), True)
check(check_valid_string(")("), False)
check(check_valid_string("(((*)"), False)
mistakes:
- Letting lo go negative.
hinglish:
## Sawaal
'(' ')' aur '*' ('*' = '(' ya ')' ya kuch nahi). Valid ho sakta hai?
## Analogy
Kamre mein guests gino jahan kuch "shayad" guests aa sakte hain, ja sakte hain ya kuch nahi karte: sabse kam aur sabse zyada possible ginti rakho. Zyada wali bhi negative → impossible; end mein kam wali zero ho sake.
## Kaise sochein
- Open count ek RANGE [lo, hi].
- hi < 0 → False; lo ≥ 0 rakho; end mein lo == 0.
## Pattern pehchano
Wildcards + open count → min/max balance.

### insert-interval
title: Insert Interval
lc: 57 insert-interval
diff: Medium
pattern: Three phases: before, overlapping, after
problem: Insert a new interval into sorted non-overlapping intervals, merging where needed.
example: [[1,3],[6,9]], new [2,5] → [[1,5],[6,9]]
analogy: Adding a new meeting to a sorted calendar: meetings that end before it stay as they are, meetings that clash get merged into one big block, and meetings after it stay as they are.
hints:
- Before (end < new start): copy.
- Overlapping: merge into new (min start, max end).
- After: copy.
brute: Append, sort, merge: O(n log n).
brutecx: O(n log n)
signal: Sorted intervals + one insertion → **linear three-phase scan**.
optimal:
- i = 0; copy while end < s; merge while start ≤ e; add merged; copy the rest.
cx: O(n)
code:
def insert(intervals, new):
    res, i, n = [], 0, len(intervals)
    s, e = new
    while i < n and intervals[i][1] < s:
        res.append(intervals[i]); i += 1
    while i < n and intervals[i][0] <= e:
        s = min(s, intervals[i][0])
        e = max(e, intervals[i][1])
        i += 1
    res.append([s, e])
    res.extend(intervals[i:])
    return res
test:
check(insert([[1, 3], [6, 9]], [2, 5]), [[1, 5], [6, 9]])
check(insert([[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], [4, 8]), [[1, 2], [3, 10], [12, 16]])
check(insert([], [5, 7]), [[5, 7]])
mistakes:
- Using < instead of <= for touching intervals.
hinglish:
## Sawaal
Sorted non-overlapping intervals mein naya interval daalo, overlap ho toh merge.
## Analogy
Sorted calendar mein nayi meeting: jo meetings pehle khatam hoti hain wo waisi hi, jo takraati hain wo ek bade block mein merge, baad wali waisi hi.
## Kaise sochein
- Pehle wale copy, overlap wale merge (min start, max end), baad wale copy.
## Pattern pehchano
Sorted intervals + ek insertion → teen phase scan.

        else:
            res.append([s, e])
    return res

            last_end = e

        if s < ends[e]:

        else:
            e += 1
    return rooms

### minimum-interval-to-include-each-query
title: Minimum Interval to Include Each Query

diff: Hard

problem: For each query q, return the size (r − l + 1) of the smallest interval containing q, or −1.
example: intervals [[1,4],[2,4],[3,6],[4,4]], queries [2,3,4,5] → [3,3,1,4]

hints:

- Sort intervals by start; for each query push every interval starting ≤ q into a min-heap by size.
- Pop intervals from the top that end before q.
- Heap top = smallest interval containing q.
brute: For each query scan all intervals.
brutecx: O(n·q)
signal: Many queries over intervals → **sort queries (offline), sweep with a heap**.

import heapq

def min_interval(intervals, queries):
    intervals = sorted(intervals)
    heap, i, ans = [], 0, {}
    for q in sorted(set(queries)):
        while i < len(intervals) and intervals[i][0] <= q:
            l, r = intervals[i]
            heapq.heappush(heap, (r - l + 1, r))
            i += 1
        while heap and heap[0][1] < q:
            heapq.heappop(heap)
        ans[q] = heap[0][0] if heap else -1
    return [ans[q] for q in queries]

optimal:
- As in the hints.

def spiral_order(m):
    res = []
    top, bottom, left, right = 0, len(m) - 1, 0, len(m[0]) - 1
    while top <= bottom and left <= right:
        res += [m[top][c] for c in range(left, right + 1)]
        top += 1
        res += [m[r][right] for r in range(top, bottom + 1)]
        right -= 1
        if top <= bottom:
            res += [m[bottom][c] for c in range(right, left - 1, -1)]
            bottom -= 1
        if left <= right:
            res += [m[r][left] for r in range(bottom, top - 1, -1)]
            left += 1
    return res

class DetectSquares:
    def __init__(self):
        self.cnt = Counter()

    def add(self, point):
        self.cnt[tuple(point)] += 1

    def count(self, point):
        x, y = point
        total = 0
        for (px, py), c in list(self.cnt.items()):
            if abs(px - x) != abs(py - y) or px == x:

            total += c * self.cnt[(x, py)] * self.cnt[(px, y)]
        return total

- As in the hints.
cx: O(32)
code:
def reverse_bits(n):
    res = 0
    for _ in range(32):
        res = (res << 1) | (n & 1)
        n >>= 1
    return res
test:

check(reverse_bits(1), 2147483648)
mistakes:
- Looping only while n > 0 (leading zeros must still be shifted in).
hinglish:
## Sawaal
32-bit unsigned integer ke bits ulte karo.
## Analogy
32 plates ka dher ek-ek karke naye dher mein rakhna: order ulta ho jaata hai. Saari 32 plates (khaali 0 wali bhi) shift karni hain, warna result galat jagah aayega.
## Kaise sochein
- Base 2 mein digit reverse jaisa.
- 32 baar: res = (res << 1) | (n & 1); n >>= 1.
## Galtiyan

### missing-number
title: Missing Number
lc: 268 missing-number
diff: Easy
pattern: XOR (or the sum formula)
problem: n distinct numbers from 0..n; one is missing. Find it.
example: [3, 0, 1] → 2
analogy: Every seat number should have exactly one ticket. Pair each seat number with each ticket using XOR; everything that's paired cancels, and the unpaired seat number is left.
hints:
- Video 1: expected sum − actual sum.
- XOR: XOR all indexes 0..n with all values; present numbers cancel.
brute: Sort and look for the gap, or a set.
brutecx: O(n log n) or O(n) space
signal: One missing from a known range → **sum difference or XOR**.
optimal:
- res = n; for i, x: res ^= i ^ x.
cx: O(n) time · O(1) space
code:
def missing_number(nums):
    res = len(nums)
    for i, x in enumerate(nums):
        res ^= i ^ x
    return res
test:
check(missing_number([3, 0, 1]), 2)
check(missing_number([0, 1]), 2)
check(missing_number([9, 6, 4, 2, 3, 5, 7, 0, 1]), 8)

- Forgetting n itself (it isn't an index).

## Sawaal
0..n mein se ek number missing hai. Dhoondo.

### sum-of-two-integers
title: Sum of Two Integers
lc: 371 sum-of-two-integers
diff: Medium
pattern: XOR = add without carry, AND << 1 = carry
problem: Add two 32-bit integers without + or −.
example: 1 + 2 = 3;   −2 + 3 = 1
analogy: Column addition in binary done in two passes: XOR writes each column's digit ignoring carries; AND-shift collects the carries; repeat until there are no carries left.
hints:
- a ^ b adds columns ignoring carries.
- (a & b) << 1 gives the carries.
- Repeat until no carry.
- Python ints are unbounded: mask to 32 bits and convert back to signed.
brute: Increment in a loop (uses +).
brutecx: O(|b|)
signal: "Add without +" → **XOR for the sum, AND-shift for the carry**.
optimal:
- mask = 0xFFFFFFFF; while b: a, b = (a ^ b) & mask, ((a & b) << 1) & mask. Convert a > 0x7FFFFFFF to negative.
cx: O(32)
code:
def get_sum(a, b):
    mask = 0xFFFFFFFF
    a &= mask
    b &= mask
    while b:
        a, b = (a ^ b) & mask, ((a & b) << 1) & mask
    return a if a <= 0x7FFFFFFF else ~(a ^ mask)
test:
check(get_sum(1, 2), 3)
check(get_sum(-2, 3), 1)
check(get_sum(-5, -7), -12)
mistakes:
- Not masking in Python (negative numbers loop forever).
hinglish:
## Sawaal
Do 32-bit integers ko + ya − ke bina jodo.
## Analogy
Binary mein column addition do pass mein: XOR har column ka digit likhta hai carry ignore karke; AND-shift carries ikattha karta hai; carry khatam hone tak dohraao.
## Kaise sochein
- a ^ b = bina carry ka jod.
- (a & b) << 1 = carries.
- Python ke int unlimited hain: 32 bits mask karo aur end mein signed banao.
## Galtiyan
Python mein mask na lagana (negative pe infinite loop).

### reverse-integer
title: Reverse Integer
lc: 7 reverse-integer
diff: Medium
pattern: Digit peeling + 32-bit range check
problem: Reverse the digits of a 32-bit signed integer; return 0 if the result leaves [−2³¹, 2³¹ − 1].
example: 123 → 321;   −123 → −321;   1534236469 → 0
analogy: Reversing a phone number written on a slip of paper that only has room for 10 digits: if the reversed number doesn't fit on the slip, you have to give up and write 0.
hints:
- Video 1's reverse-number loop, keeping the sign aside.
- Python doesn't overflow, so build the result and range-check it.
- In C++/Java you must check BEFORE multiplying (interview talking point).
brute: Reverse the string and parse, then range-check.
brutecx: O(digits)
signal: Integer reversal → **digit peeling + range guard**.
optimal:
- sign; x = abs(x); rev = rev * 10 + x % 10; x //= 10; apply sign; range check.
cx: O(digits)
code:
def reverse(x):
    sign = -1 if x < 0 else 1
    x = abs(x)
    rev = 0
    while x:
        rev = rev * 10 + x % 10
        x //= 10
    rev *= sign
    return rev if -2**31 <= rev <= 2**31 - 1 else 0
test:
check(reverse(123), 321)
check(reverse(-123), -321)
check(reverse(120), 21)
check(reverse(1534236469), 0)
mistakes:
- Using % on negative numbers in Python (−123 % 10 = 7). Work with abs().
hinglish:
## Sawaal
32-bit signed integer ke digits ulte karo; range ke bahar jaaye toh 0.
## Analogy
Kaagaz ki parchi pe likha phone number ulta karna jisme sirf 10 digits ki jagah hai: ulta number fit na ho toh haar maan ke 0 likho.
## Kaise sochein
- Video 1 wala reverse loop, sign alag rakho.
- Python overflow nahi karta: result banao, phir range check.
## Galtiyan
Negative pe % (Python mein −123 % 10 = 7). abs() use karo.
