### invert-binary-tree
title: Invert Binary Tree
lc: 226 invert-binary-tree
diff: Easy
pattern: Recursive DFS (same job at every node)
problem: Mirror a binary tree: swap the left and right child of every node.
example: [4, 2, 7, 1, 3, 6, 9] → [4, 7, 2, 9, 6, 3, 1]
analogy: Looking at a family tree in a mirror: every parent's left and right children swap places, all the way down.
hints:
- What happens at ONE node? Swap its two children.
- The same must happen to every node below: invert the left subtree and the right subtree.
- Base case: an empty tree (None) is already inverted.
brute: Recursion IS the simple solution (BFS with a queue also works).
brutecx: O(n)
signal: "Do something to every node" → **DFS recursion**: handle this node, trust the calls on the children.
optimal:
- If root is None → None. Swap children; invert both; return root.
cx: O(n) time · O(h) space (h = height)
code:
# TreeNode is defined on the Trees topic page (val, left, right).
def invert_tree(root):
    if root is None:
        return None
    root.left, root.right = invert_tree(root.right), invert_tree(root.left)
    return root
test:
check(tree_to_array(invert_tree(build_tree([4, 2, 7, 1, 3, 6, 9]))), [4, 7, 2, 9, 6, 3, 1])
check(tree_to_array(invert_tree(None)), [])
mistakes:
- Forgetting the base case (AttributeError on None).
hinglish:
## Sawaal
Tree ka mirror image banao: har node ke left aur right child swap.
## Analogy
Family tree ko shishe mein dekhna: har parent ke left-right bachche jagah badal lete hain, neeche tak.
## Kaise sochein
- EK node pe kya karna hai? Do bachche swap.
- Wahi har node pe → left subtree aur right subtree invert karo (recursion).
- Base case: None pehle se inverted hai.
## Pattern pehchano
"Har node pe kuch karo" → DFS recursion.
## Best approach
O(n).

### maximum-depth-of-binary-tree
title: Maximum Depth of Binary Tree
lc: 104 maximum-depth-of-binary-tree
diff: Easy
pattern: DFS returning a value up the tree
problem: Return the number of nodes on the longest root-to-leaf path.
example: [3, 9, 20, None, None, 15, 7] → 3
analogy: A company asking "how many management levels do we have?": every manager asks their direct reports, takes the deeper answer and adds 1 for themselves.
hints:
- Ask each child: how deep are you? Your depth = 1 + the deeper child.
- Empty tree → 0.
- Answers bubble up from the leaves.
brute: BFS counting levels (also O(n)).
brutecx: O(n)
signal: A property built from the children's answers → **post-order DFS**.
optimal:
- depth(None) = 0; depth(n) = 1 + max(depth(left), depth(right)).
cx: O(n) time · O(h) space
code:
def max_depth(root):
    if root is None:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
test:
check(max_depth(build_tree([3, 9, 20, None, None, 15, 7])), 3)
check(max_depth(None), 0)
trace:
node | left depth | right depth | returns
9 | 0 | 0 | 1
15 | 0 | 0 | 1
7 | 0 | 0 | 1
20 | 1 | 1 | 2
3 | 1 | 2 | 3
mistakes:
- Returning 1 for None.
hinglish:
## Sawaal
Root se sabse gehri leaf tak kitne nodes?
## Analogy
Company poochti hai "kitne management levels hain?": har manager apne direct reports se poochta hai, sabse gehra jawab leke apna 1 jodta hai.
## Kaise sochein
- Har bachche se poocho: tum kitne gehre ho? Meri depth = 1 + gehra bachcha.
- Khaali tree → 0.
## Pattern pehchano
Bachchon ke answers se banne wali property → post-order DFS.
## Best approach
O(n).

### diameter-of-binary-tree
title: Diameter of Binary Tree
lc: 543 diameter-of-binary-tree
diff: Easy
pattern: DFS returns height, updates a global best
problem: Return the number of edges on the longest path between any two nodes (it may not pass the root).
example: [1, 2, 3, 4, 5] → 3 (4 → 2 → 1 → 3)
analogy: The longest walk between two villages in a hill range connected by trails: every such walk climbs to some highest point and comes back down. At each hilltop, add the deepest valley on the left to the deepest on the right.
hints:
- Every path bends at a highest node; there, length = height(left) + height(right).
- Visit every node, compute left + right, keep the best.
- One DFS returns the height (for the parent) AND updates `best` (outside).
brute: For each node, compute both heights separately: O(n²).
brutecx: O(n²)
signal: "Best path anywhere" → **DFS returns one thing, updates a global best**.
optimal:
- best = 0; height(n): None → 0; l, r = heights; best = max(best, l + r); return 1 + max(l, r).
cx: O(n) time · O(h) space
code:
def diameter_of_binary_tree(root):
    best = 0

    def height(node):
        nonlocal best
        if node is None:
            return 0
        l, r = height(node.left), height(node.right)
        best = max(best, l + r)
        return 1 + max(l, r)

    height(root)
    return best
test:
check(diameter_of_binary_tree(build_tree([1, 2, 3, 4, 5])), 3)
check(diameter_of_binary_tree(build_tree([1, 2])), 1)
trace:
node | l | r | l + r | best
4 | 0 | 0 | 0 | 0
5 | 0 | 0 | 0 | 0
2 | 1 | 1 | 2 | 2
3 | 0 | 0 | 0 | 2
1 | 2 | 1 | 3 | 3
mistakes:
- Returning l + r to the parent (it needs the height).
hinglish:
## Sawaal
Kisi bhi do nodes ke beech ka sabse lamba path (edges mein).
## Analogy
Pahaadi gaon ke beech sabse lambi paidal yatra: har aisi yatra kisi sabse oonchi jagah tak chadh ke neeche utarti hai. Har choti pe left ki sabse gehri ghaati + right ki sabse gehri ghaati jodo.
## Kaise sochein
- Har path kisi sabse oonche node pe mudta hai: wahan length = left height + right height.
- Har node pe ye nikaalo, best rakho.
- Ek DFS parent ko height lautata hai, aur bahar wala `best` update karta hai.
## Pattern pehchano
"Kahin bhi best path" → DFS + global best (`nonlocal best`).
## Best approach
O(n).
## Galtiyan
Parent ko l + r lautana (usse height chahiye).

### balanced-binary-tree
title: Balanced Binary Tree
lc: 110 balanced-binary-tree
diff: Easy
pattern: DFS with a "failed" signal
problem: A tree is balanced if at every node the heights of the two subtrees differ by at most 1. Return whether it is.
example: [3, 9, 20, None, None, 15, 7] → True
analogy: A school inspector checking every classroom's two benches for fairness. Once any room fails, the report can say "fail" immediately without re-measuring everything.
hints:
- Checking heights separately at every node repeats work: O(n²).
- Compute height bottom-up and check balance at the same time.
- Return −1 as an "already unbalanced" signal so parents stop early.
brute: At each node call height() on both children.
brutecx: O(n²)
signal: Validate a property at every node → **post-order DFS carrying info up**.
optimal:
- h(n): None → 0; l, r; if l == −1 or r == −1 or |l − r| > 1 → −1; else 1 + max.
cx: O(n) time · O(h) space
code:
def is_balanced(root):
    def h(node):
        if node is None:
            return 0
        l, r = h(node.left), h(node.right)
        if l == -1 or r == -1 or abs(l - r) > 1:
            return -1
        return 1 + max(l, r)
    return h(root) != -1
test:
check(is_balanced(build_tree([3, 9, 20, None, None, 15, 7])), True)
check(is_balanced(build_tree([1, 2, 2, 3, 3, None, None, 4, 4])), False)
check(is_balanced(None), True)
mistakes:
- Only checking the root's two subtrees.
hinglish:
## Sawaal
Har node pe dono subtrees ki height ka farak ≤ 1? Tab balanced.
## Analogy
School inspector har classroom ki do benches ki fairness check karta hai. Ek bhi room fail hua toh report turant "fail" likh deti hai, sab dobara naapne ki zaroorat nahi.
## Kaise sochein
- Har node pe alag height nikaalna O(n²).
- Neeche se height nikaalo aur saath hi balance check karo.
- −1 = "already unbalanced" signal.
## Pattern pehchano
Har node pe property validate → post-order DFS.
## Best approach
O(n).

### same-tree
title: Same Tree
lc: 100 same-tree
diff: Easy
pattern: Parallel DFS on two trees
problem: Return True if two binary trees have the same shape and values.
example: [1, 2, 3] and [1, 2, 3] → True;   [1, 2] and [1, None, 2] → False
analogy: Two people walking through identical-looking buildings room by room, comparing: same room here? Same doors? The first difference ends the check.
hints:
- Walk both trees together.
- Both None → same. One None → different. Different values → different.
- Otherwise left with left AND right with right.
brute: Serialise both and compare strings.
brutecx: O(n)
signal: Comparing two trees → **recursion on pairs of nodes**.
optimal:
- same(p, q): both None → True; one None or values differ → False; return same(left) and same(right).
cx: O(n) time · O(h) space
code:
def is_same_tree(p, q):
    if p is None and q is None:
        return True
    if p is None or q is None or p.val != q.val:
        return False
    return is_same_tree(p.left, q.left) and is_same_tree(p.right, q.right)
test:
check(is_same_tree(build_tree([1, 2, 3]), build_tree([1, 2, 3])), True)
check(is_same_tree(build_tree([1, 2]), build_tree([1, None, 2])), False)

- Comparing only the values in a traversal ([1, 2] and [1, None, 2] have the same values).
hinglish:
## Sawaal
Do trees ka shape aur values same hain?
## Analogy
Do log bilkul ek jaisi dikhne wali buildings mein room-by-room saath chalte hue compare karte hain. Pehla farak mila toh check khatam.
## Kaise sochein
- Dono None → same. Ek None → alag. Values alag → alag.
- Warna left-left AUR right-right.
## Pattern pehchano
Do trees compare → nodes ke pairs pe recursion.
## Best approach
O(n).

### subtree-of-another-tree
title: Subtree of Another Tree
lc: 572 subtree-of-another-tree
diff: Easy
pattern: DFS + Same Tree at each node
problem: Return True if `sub` matches some node of `root` together with all its descendants.
example: root [3, 4, 5, 1, 2], sub [4, 1, 2] → True
analogy: Checking whether a small family photo appears anywhere inside a big family tree: try placing it at every person, and compare generation by generation.
hints:
- Could the match start at this node? Use is_same_tree(node, sub).
- If not here, try the left and right subtrees.
- Reuse your Same Tree solution: big problems are built from small solved ones.
brute: This is the standard solution: O(m·n).
brutecx: O(m·n)
signal: "Does pattern B occur inside A?" → **try every start + a matcher**.
optimal:
- sub None → True; root None → False; same(root, sub) → True; else recurse left or right.
cx: O(m·n) time · O(h) space
code:
def same(p, q):
    if p is None and q is None:
        return True
    if p is None or q is None or p.val != q.val:
        return False
    return same(p.left, q.left) and same(p.right, q.right)

def is_subtree(root, sub):
    if sub is None:
        return True
    if root is None:
        return False
    if same(root, sub):
        return True
    return is_subtree(root.left, sub) or is_subtree(root.right, sub)
test:
check(is_subtree(build_tree([3, 4, 5, 1, 2]), build_tree([4, 1, 2])), True)
check(is_subtree(build_tree([3, 4, 5, 1, 2, None, None, None, None, 0]), build_tree([4, 1, 2])), False)
mistakes:
- Checking only whether sub's values appear somewhere.
hinglish:
## Sawaal
Kya `sub` tree, `root` ke kisi node aur uske saare descendants se bilkul match karta hai?
## Analogy
Chhoti family photo badi family tree mein kahin hai kya: har insaan pe rakh ke dekho, generation-by-generation compare karo.
## Kaise sochein
- Is node se match shuru ho sakta hai? `same(node, sub)`.
- Nahi → left aur right subtree mein try.
- Same Tree wala solution reuse karo.
## Pattern pehchano
"B, A ke andar kahin hai?" → har start + matcher.
## Best approach
O(m·n).

### lowest-common-ancestor-of-a-binary-search-tree
title: Lowest Common Ancestor of a BST
lc: 235 lowest-common-ancestor-of-a-binary-search-tree
diff: Medium
pattern: Use the BST ordering to walk down
problem: In a BST, return the lowest node that has both p and q as descendants (a node counts as its own descendant).
example: BST [6, 2, 8, 0, 4, 7, 9, None, None, 3, 5], p = 2, q = 8 → 6
analogy: Two addresses in the same city. Start at the city centre and walk down the road signs: while both addresses are in the same direction, keep walking; the junction where their directions split is their meeting point.
hints:
- In a BST, if both values are smaller than the node, both are in the LEFT subtree.
- Both larger → go right.
- Otherwise they split here (or one IS this node): this is the LCA.
brute: Find both root-to-node paths and compare.
brutecx: O(n)
signal: **BST** → the ordering tells you which way to go.
optimal:
- cur = root; while cur: both smaller → left; both larger → right; else return cur.
cx: O(h) time · O(1) space
code:
def lowest_common_ancestor(root, p, q):
    cur = root
    while cur:
        if p < cur.val and q < cur.val:
            cur = cur.left
        elif p > cur.val and q > cur.val:
            cur = cur.right
        else:
            return cur
    return None
test:
t = build_tree([6, 2, 8, 0, 4, 7, 9, None, None, 3, 5])
check(lowest_common_ancestor(t, 2, 8).val, 6)
check(lowest_common_ancestor(t, 2, 4).val, 2)
check(lowest_common_ancestor(t, 3, 5).val, 4)
mistakes:
- Ignoring the BST property and doing a general-tree search.
hinglish:
## Sawaal
BST mein p aur q ka lowest common ancestor.
## Analogy
Ek hi shehar ke do address. City centre se road signs follow karo: jab tak dono address ek hi direction mein hain, chalte raho; jis chauraahe pe unki directions alag hoti hain wahi milne ki jagah hai.
## Kaise sochein
- Dono node se chhote → left. Dono bade → right.
- Warna yahi split hai → answer.
## Pattern pehchano
BST → order se direction decide.
## Best approach
O(h).

### binary-tree-level-order-traversal
title: Binary Tree Level Order Traversal
lc: 102 binary-tree-level-order-traversal
diff: Medium
pattern: BFS with a queue (level by level)
problem: Return the values level by level, left to right.
example: [3, 9, 20, None, None, 15, 7] → [[3], [9, 20], [15, 7]]
analogy: Ripples from a stone dropped in water: first the centre, then the first ring, then the second ring. A queue processes the tree ring by ring.
hints:
- Level by level = BFS = a queue (deque).
- At the start of each round the queue holds EXACTLY one level: record its size and process that many nodes.
- While processing, enqueue children: they're the next level.
brute: DFS passing the depth and appending to result[depth] (also O(n)).
brutecx: O(n)
signal: "Level by level / nearest first" → **BFS grouped by queue size**.
optimal:
- q = deque([root]); while q: level = [] of len(q) pops; enqueue children; res.append(level).
cx: O(n) time · O(n) space
code:
from collections import deque

def level_order(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        res.append(level)
    return res
test:
check(level_order(build_tree([3, 9, 20, None, None, 15, 7])), [[3], [9, 20], [15, 7]])
check(level_order(None), [])
trace:
round | queue at start | level
1 | [3] | [3]
2 | [9, 20] | [9, 20]
3 | [15, 7] | [15, 7]
mistakes:
- Using a list's pop(0) (O(n) each); use deque.popleft().
hinglish:
## Sawaal
Tree ki values level-by-level, left se right.
## Analogy
Paani mein patthar girane se lehrein: pehle beech, phir pehla ghera, phir doosra. Queue tree ko ghera-dar-ghera process karti hai.
## Kaise sochein
- Level by level = BFS = queue (deque).
- Har round ki shuruaat mein queue mein EXACTLY ek level hota hai: uska size note karo aur utne nodes nikaalo.
- Nikaalte waqt bachche daalo: wo agla level.
## Pattern pehchano
"Level by level / sabse paas pehle" → BFS.
## Best approach
O(n).

### binary-tree-right-side-view
title: Binary Tree Right Side View
lc: 199 binary-tree-right-side-view
diff: Medium
pattern: BFS, last node of each level
problem: Standing on the right of the tree, return the values you can see top to bottom.
example: [1, 2, 3, None, 5, None, 4] → [1, 3, 4]
analogy: Looking at a building from the right side: on each floor you only see the rightmost window.
hints:
- One node per level is visible: the rightmost.
- Level-order BFS; record the last node of each level.
- (DFS alternative: right before left, record the first node at each new depth.)
brute: Build all levels, take the last of each.
brutecx: O(n)
signal: "One node per level" → **BFS by level**.
optimal:
- BFS; when i == size − 1, record node.val.
cx: O(n) time · O(n) space
code:
from collections import deque

def right_side_view(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        size = len(q)
        for i in range(size):
            node = q.popleft()
            if i == size - 1:
                res.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
    return res
test:
check(right_side_view(build_tree([1, 2, 3, None, 5, None, 4])), [1, 3, 4])
check(right_side_view(build_tree([1, 2])), [1, 2])
mistakes:
- Only following right children (a left branch can stick out lower down).
hinglish:
## Sawaal
Tree ke right side khade hoke upar se neeche kaun se nodes dikhenge?
## Analogy
Building ko right side se dekho: har floor pe sirf sabse right wali khidki dikhti hai.
## Kaise sochein
- Har level ka ek node dikhta hai: sabse right wala.
- Level-order BFS, har level ka aakhri node record.
## Pattern pehchano
"Har level ka ek node" → BFS by level.
## Best approach
O(n).
## Galtiyan

problem: A node is "good" if no node on the path from the root to it has a greater value. Count good nodes.

analogy: A hiking trail: a viewpoint is "good" if it's at least as high as every point you passed on the way. You carry the "highest so far" number in your pocket as you walk.

def good_nodes(root):

        mx = max(mx, node.val)
        return good + dfs(node.left, mx) + dfs(node.right, mx)

### validate-binary-search-tree
title: Validate Binary Search Tree
lc: 98 validate-binary-search-tree
diff: Medium
pattern: DFS with an allowed (low, high) range
problem: Is the tree a valid BST (everything in a left subtree < node < everything in the right subtree)?
example: [2, 1, 3] → True;   [5, 1, 4, None, None, 3, 6] → False
analogy: Seating by roll number in a hall: going left means "smaller than the person you just passed", going right means "bigger". Each seat inherits limits from EVERY person above it, not just the nearest one.
hints:
- node.left < node < node.right is NOT enough: a grandchild can break the rule.
- Each node has an allowed range. The root allows (−inf, +inf).
- Left: the upper bound becomes the parent's value. Right: the lower bound does.
brute: In-order traversal must be strictly increasing (also O(n), with O(n) space).
brutecx: O(n)
signal: Constraint inherited from ancestors → **DFS with bounds passed down**.
optimal:
- valid(n, lo, hi): None → True; not lo < val < hi → False; recurse left (lo, val), right (val, hi).
cx: O(n) time · O(h) space
code:
def is_valid_bst(root):
    def valid(node, lo, hi):
        if node is None:
            return True
        if not (lo < node.val < hi):
            return False
        return valid(node.left, lo, node.val) and valid(node.right, node.val, hi)
    return valid(root, float("-inf"), float("inf"))
test:
check(is_valid_bst(build_tree([2, 1, 3])), True)
check(is_valid_bst(build_tree([5, 1, 4, None, None, 3, 6])), False)
check(is_valid_bst(build_tree([5, 4, 6, None, None, 3, 7])), False)
mistakes:
- Only comparing a node with its direct children.
hinglish:
## Sawaal
Kya tree valid BST hai (left subtree ka sab < node < right subtree ka sab)?
## Analogy
Hall mein roll number se baithna: left jaana matlab "jisse abhi guzre usse chhota", right matlab "bada". Har seat ko upar ke HAR insaan se limits milti hain, sirf paas wale se nahi.
## Kaise sochein
- Sirf bachchon se compare kaafi nahi; grandchild bhi rule tod sakta hai.
- Har node ki ek allowed range. Root: (−inf, +inf).
- Left jao → upper bound = parent. Right → lower bound = parent.
## Pattern pehchano
Ancestors se aane wali condition → bounds wala DFS.
## Best approach
O(n).
## Galtiyan
Sirf direct children compare karna.

    p = 0

            return None
        root = TreeNode(preorder[p])

        if node is None:

        r = max(0, gain(node.right))

    return best

### implement-trie-prefix-tree
title: Implement Trie (Prefix Tree)

class TrieNode:
    def __init__(self):
        self.children = {}
        self.end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        cur = self.root
        for ch in word:
            cur = cur.children.setdefault(ch, TrieNode())
        cur.end = True

    def _find(self, s):
        cur = self.root
        for ch in s:
            if ch not in cur.children:
                return None
            cur = cur.children[ch]
        return cur

    def search(self, word):
        node = self._find(word)
        return node is not None and node.end

    def startsWith(self, prefix):
        return self._find(prefix) is not None

class WordDictionary:
    def __init__(self):
        self.root = {}

    def addWord(self, word):
        cur = self.root
        for ch in word:
            cur = cur.setdefault(ch, {})
        cur["$"] = True

    def search(self, word):
        def dfs(node, i):
            if i == len(word):
                return "$" in node
            ch = word[i]
            if ch == ".":
                return any(dfs(child, i + 1) for key, child in node.items() if key != "$")
            return ch in node and dfs(node[ch], i + 1)
        return dfs(self.root, 0)

- Mark cells visited on the path; restore when backtracking.

code:
def find_words(board, words):
    root = {}
    for w in words:
        node = root
        for ch in w:
            node = node.setdefault(ch, {})
        node["$"] = w
    rows, cols = len(board), len(board[0])
    res = []

    def dfs(r, c, node):
        ch = board[r][c]
        nxt = node.get(ch)
        if not nxt:
            return
        if "$" in nxt:
            res.append(nxt.pop("$"))
        board[r][c] = "#"
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != "#":
                dfs(nr, nc, nxt)
        board[r][c] = ch

    for r in range(rows):
        for c in range(cols):
            dfs(r, c, root)
    return res

import heapq

def last_stone_weight(stones):
    h = [-s for s in stones]
    heapq.heapify(h)
    while len(h) > 1:
        y = -heapq.heappop(h)
        x = -heapq.heappop(h)
        if y != x:
            heapq.heappush(h, -(y - x))
    return -h[0] if h else 0

O(n log k).

### kth-largest-element-in-an-array
title: Kth Largest Element in an Array
lc: 215 kth-largest-element-in-an-array
diff: Medium
pattern: Min-heap of size k (or Quickselect)
problem: Return the kth largest element (in sorted order, duplicates count).
example: [3, 2, 1, 5, 6, 4], k = 2 → 5
analogy: A talent contest that only has k medals: keep the current k best in a group; the weakest medal-holder is the kth best.
hints:
- Sorting: O(n log n).
- A min-heap of the k largest values has the kth largest on top.
- (Advanced: Quickselect partitions like quicksort and recurses into one side: O(n) average.)
brute: `sorted(nums, reverse=True)[k − 1]`.
brutecx: O(n log n)
signal: **kth largest** → min-heap of size k.
optimal:
- For x: push; if size > k: pop. Return heap[0].
cx: O(n log k) time · O(k) space
code:
import heapq

def find_kth_largest(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]

### task-scheduler
title: Task Scheduler
lc: 621 task-scheduler
diff: Medium
pattern: Greedy maths on the most frequent task
problem: Tasks are letters; identical tasks must be at least n time units apart. Return the minimum total time (idle allowed).
example: [A, A, A, B, B, B], n = 2 → 8 (A B idle A B idle A B)
analogy: A washing machine that needs a cool-down after each wash of the same type of load. The most frequent load type sets the skeleton; other loads fill the gaps.
hints:
- The most frequent task sets the frame: A _ _ A _ _ A → (max_count − 1) gaps of length n.
- Frame = (max_count − 1) × (n + 1) + (number of tasks tied at max_count).
- If there are more tasks than slots, no idle time: the answer is len(tasks).
- Answer = max(len(tasks), frame).
brute: Simulate with a max-heap and a cooldown queue (also common).
brutecx: O(total time · log 26)
signal: "Schedule with cooldowns" → **arrange around the most frequent item**.
optimal:
- counts = Counter(tasks).values(); m = max; ties = count of m; return max(len, (m − 1)(n + 1) + ties).
cx: O(n) time · O(26) space
code:
from collections import Counter

def least_interval(tasks, n):
    counts = Counter(tasks).values()
    m = max(counts)
    ties = sum(1 for c in counts if c == m)
    return max(len(tasks), (m - 1) * (n + 1) + ties)
test:
check(least_interval(["A", "A", "A", "B", "B", "B"], 2), 8)
check(least_interval(["A", "C", "A", "B", "D", "B"], 1), 6)
check(least_interval(["A", "A", "A", "B", "B", "B"], 3), 10)
trace:
step | value
counts | A: 3, B: 3
max count | 3
ties | 2
frame | (3 − 1) × (2 + 1) + 2 = 8
answer | max(6, 8) = 8
mistakes:
- Forgetting the ties (the last row holds every task tied at the max).
hinglish:
## Sawaal
Same tasks ke beech kam se kam n units ka gap. Minimum total time?
## Analogy
Washing machine jise same type ke load ke baad cool-down chahiye. Sabse zyada baar aane wala load skeleton banata hai; baaki loads gaps bharte hain.
## Kaise sochein
- Sabse frequent task frame banata hai: (max − 1) gaps, har gap n ka.
- Frame = (max − 1) × (n + 1) + max count wale tasks ki ginti.
- Tasks slots se zyada → idle nahi: answer = len(tasks).
## Pattern pehchano
Cooldown scheduling → sabse frequent ke around arrange.
## Best approach
O(n).
## Galtiyan
Ties bhoolna.

### design-twitter
title: Design Twitter
lc: 355 design-twitter
diff: Medium
pattern: Merge k sorted feeds with a heap
problem: postTweet(user, id), getNewsFeed(user) (10 most recent tweets from the user and followees), follow, unfollow.
example: post(1, 5); feed(1) → [5]; follow(1, 2); post(2, 6); feed(1) → [6, 5]; unfollow(1, 2); feed(1) → [5]
analogy: Your feed is like merging several friends' diaries that are each written in time order: keep a finger on the latest entry of each diary and repeatedly read the newest one among them.
hints:
- Store each user's tweets as (time, id) with a global counter for time.
- Each followee's list is already sorted by time: the feed = merge k sorted lists, take 10.
- A max-heap seeded with each followee's newest tweet (like Merge K Lists).
brute: Collect every tweet of every followee, sort, take 10.
brutecx: O(T log T) per feed
signal: "Top 10 across several sorted lists" → **heap k-way merge**.
optimal:
- For each person with tweets push (−time, id, person, index). Pop up to 10; after each pop push that person's previous tweet.
cx: O(k log k + 10 log k) per feed
code:
import heapq
from collections import defaultdict

class Twitter:
    def __init__(self):
        self.time = 0
        self.tweets = defaultdict(list)
        self.follows = defaultdict(set)

    def postTweet(self, user, tweet_id):
        self.tweets[user].append((self.time, tweet_id))
        self.time += 1

    def getNewsFeed(self, user):
        heap = []
        for p in self.follows[user] | {user}:
            if self.tweets[p]:
                i = len(self.tweets[p]) - 1
                t, tid = self.tweets[p][i]
                heap.append((-t, tid, p, i))
        heapq.heapify(heap)
        feed = []
        while heap and len(feed) < 10:
            _, tid, p, i = heapq.heappop(heap)
            feed.append(tid)
            if i > 0:
                t, nid = self.tweets[p][i - 1]
                heapq.heappush(heap, (-t, nid, p, i - 1))
        return feed

    def follow(self, a, b):
        if a != b:
            self.follows[a].add(b)

    def unfollow(self, a, b):
        self.follows[a].discard(b)
test:
tw = Twitter()
tw.postTweet(1, 5)
check(tw.getNewsFeed(1), [5])
tw.follow(1, 2)
tw.postTweet(2, 6)
check(tw.getNewsFeed(1), [6, 5])
tw.unfollow(1, 2)
check(tw.getNewsFeed(1), [5])
mistakes:
- Forgetting that users see their own tweets.
hinglish:
## Sawaal
Chhota Twitter: post, follow, unfollow, aur news feed (10 sabse naye tweets, apne + follow kiye logon ke).
## Analogy
Feed kai doston ki diaries merge karne jaisa hai jo har ek time order mein likhi hain: har diary ki latest entry pe ungli rakho aur baar-baar unme se sabse nayi padho.
## Kaise sochein
- Har user ke tweets (time, id) ke saath; global counter se time.
- Har followee ki list time se sorted → feed = k sorted lists merge, 10 lo.
- Har followee ka newest tweet max-heap mein (Merge K Lists jaisa).
## Pattern pehchano
"Kai sorted lists mein top 10" → heap k-way merge.
## Best approach
Feed ~O(k log k).
## Galtiyan
User ko apne hi tweets na dikhana.

### find-median-from-data-stream
title: Find Median from Data Stream
lc: 295 find-median-from-data-stream
diff: Hard
pattern: Two heaps (lower half max-heap, upper half min-heap)
problem: addNum(x) and findMedian() efficiently while numbers keep arriving.
example: add 1, add 2 → 1.5; add 3 → 2.0
analogy: Students entering a hall are split into a "shorter half" room and a "taller half" room of equal size. The tallest of the short room and the shortest of the tall room stand at the door, and the median is right there.
hints:
- The median needs only the middle: split into a LOWER half and an UPPER half.
- Lower half: max-heap (top = biggest small number). Upper half: min-heap.
- Keep sizes equal, or the lower half one bigger.
- Median = lower top (odd) or the average of both tops (even).
brute: Insert into a sorted list: O(n) per add.
brutecx: O(n) per add
signal: Running median → **two heaps**.
optimal:
- add: push −x to lo; move lo's top to hi; if hi bigger, move hi's top back to lo.
- median: len(lo) > len(hi) → −lo[0]; else (−lo[0] + hi[0]) / 2.
cx: O(log n) add · O(1) median
code:
import heapq

class MedianFinder:
    def __init__(self):
        self.lo = []
        self.hi = []

    def addNum(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def findMedian(self):
        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2
test:

m.addNum(1); m.addNum(2)
check(m.findMedian(), 1.5)
m.addNum(3)
check(m.findMedian(), 2.0)
trace:

1 | [1] | [] | 1
2 | [1] | [2] | 1.5
3 | [2, 1] | [3] | 2

- Pushing into one heap by comparison without rebalancing.

## Kaise sochein
