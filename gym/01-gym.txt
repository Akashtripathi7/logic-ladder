## module: g1 | How to think: the recipe
summary: The 7-step recipe for any problem, how to trace code by hand, and the habit that builds logic fastest.
=== en
### Logic is a habit, not a talent
People who "have logic" are not born with it. They follow a process so often that it becomes automatic. This gym trains that process on small problems until it's second nature.

### The 7-step recipe
1. **Understand** — say the problem in your own words. What goes in? What comes out? What are the edge cases (empty, one item, negatives, duplicates)?
2. **Examples by hand** — solve 2–3 tiny cases with pen and paper, slowly. Watch what YOUR hands do: that is the algorithm.
3. **Brute force** — write the simplest correct idea, even if slow.
4. **Improve** — find the repeated work; which tool removes it (a set, a dict, sorting, two pointers, a formula)?
5. **Code** — translate the plain-English steps.
6. **Trace & test** — run your examples through the code by hand.
7. **Analyse** — time and space in Big O.

> **Analogy:** A doctor doesn't guess. Symptoms (clues in the problem) → diagnosis (the pattern) → treatment (the code template). Steps 1–2 are the examination, and most beginners skip them.

### Worked example: "count how many numbers in a list are bigger than the number before them"
1. **Understand:** input a list like `[3, 5, 2, 8, 9]`; output a count. Compare each item with its left neighbour. The first item has no neighbour.
2. **By hand:** 5 > 3 ✓, 2 > 5 ✗, 8 > 2 ✓, 9 > 8 ✓ → 3. My eyes looked at pairs (previous, current).
3. **Brute force = the hand method:** loop from index 1, compare `nums[i]` with `nums[i-1]`, count.
4. Already O(n): nothing to improve.
5. **Code:**
```python
def count_rises(nums):
    count = 0
    for i in range(1, len(nums)):
        if nums[i] > nums[i - 1]:
            count += 1
    return count
```
6. **Trace:**
| i | nums[i-1] | nums[i] | rise? | count |
|---|---|---|---|---|
| 1 | 3 | 5 | yes | 1 |
| 2 | 5 | 2 | no | 1 |
| 3 | 2 | 8 | yes | 2 |
| 4 | 8 | 9 | yes | 3 |
7. O(n) time, O(1) space. Edge case `[]` or `[7]`: range(1, 0/1) is empty → 0 ✓.

### How to trace like a computer
- Draw a column for **every variable** and a row for **every step** (every loop lap).
- Update values exactly as the code says, not as you *think* it should behave.
- Write down every `print` output as it happens.
- When your trace and the real output differ, the first differing row is where your understanding (or the code) is wrong.

### The habit that builds logic fastest
**Predict, then run.** Before running any code, write down what you think it prints. Then run it. Every surprise is a lesson. The drills in this gym are built around this.

### When stuck
Shrink the problem (n = 1, 2, 3), draw it, write the brute force, ask "what if it were sorted / what if I had a dict?", and give yourself 20–25 minutes before looking at a hint.

- Har **variable** ka ek column, har **step** (loop lap) ki ek row.
- Values waise hi update karo jaise code kehta hai, waise nahi jaise tumhe *lagta* hai.
- Har `print` ka output jaise hi ho, likh lo.
- Tumhara trace aur asli output alag aayein, toh pehli alag row hi galti ki jagah hai.

### Logic sabse fast banane wali aadat
**Pehle predict, phir run.** Koi bhi code chalane se pehle likho ki tumhe kya lagta hai wo print karega. Phir run karo. Har surprise ek lesson hai. Is gym ke drills isi pe bane hain.

## module: g2 | Loop mastery
summary: Counting iterations, tracing accumulators, while loops with digits, and choosing the right loop.
=== en
### The three questions for every loop
1. **First value** of the loop variable?
2. **Last value**?
3. **What changes** each lap, and what is it at the end?
Answer these before writing or reading any loop and off-by-one errors disappear.

### Counting laps
`range(a, b, s)` with positive step runs `ceil((b − a) / s)` times (0 if b ≤ a). Don't memorise the formula; **list the first few values and the last one**.

### Accumulators and counters
- Sum starts at 0, product at 1, "best max" at the first element or `float("-inf")`, a result list at `[]`, a result string at `""`.
- Update inside the loop, read the answer after the loop.

### Loop with digits
`while n > 0: d = n % 10; n //= 10` visits digits from right to left. To visit from left to right, convert to a string, or reverse first.

### Loop with two indexes
Many problems walk two indexes: `i` over one list and `j` over another (merging), or `l` and `r` towards each other (palindromes). Each lap, decide which one moves.

### Choosing the loop
| Situation | Loop |
|---|---|
| each item of a list/string | `for x in items` |
| need the index | `for i in range(len(a))` or `enumerate` |
| unknown number of laps | `while condition` |
| stop early | `break` (or `return` inside a function) |

> **Tip:** When a loop confuses you, add `print(i, variable)` as the first line of the body and run it. Seeing the laps is the fastest cure.
=== hi
### Har loop ke teen sawaal
1. Loop variable ki **pehli value**?
2. **Aakhri value**?
3. Har lap mein **kya badalta** hai, aur end mein kya hota hai?
Loop likhne ya padhne se pehle ye jawab do, off-by-one errors gayab.

### Laps ginna
Formula yaad mat karo; **pehli kuch values aur aakhri value likh do**.

### Accumulators aur counters

### Digits wala loop

### Do indexes wala loop
Kai problems mein do index chalte hain: `i` ek list pe aur `j` doosri pe (merge), ya `l` aur `r` ek doosre ki taraf (palindrome). Har lap decide karo kaun aage badhega.

### Kaunsa loop
Har item → `for x in items`; index chahiye → `range(len(a))` ya `enumerate`; laps ka pata nahi → `while`; jaldi rukna → `break`.

> **Tip:** Loop confuse kare toh body ki pehli line mein `print(i, variable)` daal ke chalao. Laps dekhna sabse fast ilaaj hai.

## module: g3 | Pattern printing
summary: The table method for star and number patterns: rows, what's in each row, find the formula.
=== en
### The table method (again, because it works)
1. Count the rows → the outer loop, usually `for i in range(1, n + 1)`.
2. Look at one row: how many spaces? how many stars/numbers? what values?
3. Make a table for rows 1..n.
4. Find the formula in terms of i and n.
5. Build each row as a string and print it.

### Formulas you'll meet again and again
| Shape | spaces | stars |
|---|---|---|
| right triangle | 0 | i |
| inverted triangle | 0 | n − i + 1 |
| right-aligned triangle | n − i | i |
| pyramid | n − i | 2i − 1 |
| inverted pyramid | i − 1 | 2(n − i) + 1 |

> **Tip:** If a column in your table goes up by 2 each row, the formula has `2i`. If it goes down by 1, it has `−i`. Then fix the constant using row 1.

### Numbers instead of stars
- Row i shows 1..i → `" ".join(str(j) for j in range(1, i + 1))`.
- Row i shows i, i times → `" ".join([str(i)] * i)`.
- Floyd's triangle counts continuously 1, 2 3, 4 5 6 → keep a counter **outside** the loops.

### Why patterns matter
Patterns train exactly the skill DSA needs: turning a picture into a relationship between loop variables. Once you can derive "2i − 1" from a table, you can derive "n − i − 1" for a two-pointer bound.
=== hi
### Table method (phir se, kyunki ye kaam karta hai)
1. Rows gino → outer loop, aksar `for i in range(1, n + 1)`.
2. Ek row dekho: kitne spaces? kitne stars/numbers? kaunsi values?
3. Rows 1..n ki table banao.
4. i aur n ke terms mein formula dhoondo.
5. Har row string bana ke print karo.

### Baar-baar aane wale formulas
Right triangle: stars = i. Ulta triangle: stars = n − i + 1. Right-aligned: spaces = n − i, stars = i. Pyramid: spaces = n − i, stars = 2i − 1. Ulta pyramid: spaces = i − 1, stars = 2(n − i) + 1.

> **Tip:** Table ka koi column har row 2 se badhe toh formula mein `2i` hai. 1 se ghate toh `−i`. Phir row 1 se constant theek karo.

### Stars ki jagah numbers
Row i mein 1..i; row i mein i, i baar; Floyd's triangle mein ginti chalti rehti hai (1, 2 3, 4 5 6) → counter loops ke **bahar** rakho.

### Patterns kyun zaroori hain
Patterns wahi skill sikhate hain jo DSA ko chahiye: picture ko loop variables ke relation mein badalna. Table se "2i − 1" nikaal liya toh two-pointer ki "n − i − 1" wali bound bhi nikaal loge.

## module: g4 | List logic
summary: Walking lists with indexes, neighbours, max/min, counting, building new lists, in-place changes and 2-D grids.
=== en
### Thinking in positions
A list is positions 0..n−1. Most list problems are about **which positions you look at, and in what order**:
- one by one: `for i in range(n)`
- with the neighbour: `nums[i]` and `nums[i - 1]` (start i at 1) or `nums[i + 1]` (stop at n − 1)
- from both ends: `l = 0, r = n − 1`
- every pair: `for i … for j in range(i + 1, n)` (O(n²), the brute force)

### Build a new list, or change in place?
- **New list** (easiest, safest): `result = []` then `append`.
- **In place** (O(1) extra space, often asked): swap elements, or use a **write pointer** that marks where the next kept element goes:
```python
def remove_zeros(nums):
    write = 0
    for x in nums:
        if x != 0:
            nums[write] = x
            write += 1
    return nums[:write]
```
> **Analogy:** A write pointer is a person at the front of a bus: every time a kept passenger boards, they're seated at the next free seat.

### Max, min and "second best"
Best-so-far variables, updated in the right order. For the top 2, keep `first` and `second`; a new maximum pushes the old first down.

### Frequencies
Counting with a dict turns "how many times does x appear?" from O(n) per question into O(1).

### Grids
`grid[r][c]`, `rows = len(grid)`, `cols = len(grid[0])`. Neighbours: `(r-1,c) (r+1,c) (r,c-1) (r,c+1)`, always check `0 <= nr < rows and 0 <= nc < cols`.
=== hi
### Positions mein socho
List positions 0..n−1 hai. Zyaadatar list problems ye hain ki **kaunsi positions dekhni hain, aur kis order mein**:
- ek-ek karke: `for i in range(n)`
- pados ke saath: `nums[i]` aur `nums[i - 1]` (i ko 1 se shuru karo) ya `nums[i + 1]` (n − 1 pe ruko)
- dono ends se: `l = 0, r = n − 1`
- har pair: nested loop (O(n²), brute force)

### Nayi list ya wahi pe badlo?
- **Nayi list** (aasaan, safe): `result = []` phir `append`.
- **In place** (O(1) extra space, aksar poocha jaata hai): swap karo, ya **write pointer** use karo jo batata hai agla rakha jaane wala element kahan jayega.

> **Analogy:** Write pointer bus ke aage khada ek conductor hai: jab bhi koi rakha jaane wala passenger chadhta hai, use agli khaali seat pe bitha deta hai.

### Max, min aur "second best"
Best-so-far variables, sahi order mein update. Top 2 ke liye `first` aur `second`; naya maximum purane first ko neeche dhakel deta hai.

### Frequencies
Dict se counting karo toh "x kitni baar aaya?" O(n) ki jagah O(1) mein.

### Grids
`grid[r][c]`, `rows = len(grid)`, `cols = len(grid[0])`. Pados: `(r-1,c) (r+1,c) (r,c-1) (r,c+1)`, hamesha `0 <= nr < rows and 0 <= nc < cols` check karo.

## module: g5 | String logic
summary: Characters as positions, comparing from both ends, counting characters, building strings, and word-level work.
=== en
### Strings are lists you can't change
Everything from list logic applies (positions, neighbours, both ends), with two differences:
- You can't assign `s[i] = x`. Build a new string, or work on `list(s)` and `"".join` at the end.
- Strings have powerful methods (`split`, `join`, `lower`, `isalpha`…). Use them.

### Four string patterns
1. **Character counting** — `Counter(s)` or a 26-slot list with `ord(ch) - ord('a')`. Anagrams, first unique character, pangrams.
2. **Two ends** — `l, r = 0, len(s) - 1`, move inward. Palindromes, reversing.
3. **Runs** — compare `s[i]` with `s[i - 1]` to detect where a group of equal characters starts or ends. Compression, counting words.
4. **Word level** — `s.split()` first, then work with the list of words. Reversing words, title case, longest word.

> **Analogy:** Treat a sentence like a string of beads (characters) when the problem talks about letters, and like a row of boxes (words) when it talks about words. Choosing the right view is half the solution.

### Case and noise
Problems often say "ignore case" (use `lower()`) or "ignore non-letters" (use `ch.isalnum()` / `ch.isalpha()`). Clean first, then solve, or skip noise inside two-pointer loops.

q: Write `is_palindrome(s)` with two pointers, ignoring case and non-letters/digits.
answer:
def is_palindrome(s):
    l, r = 0, len(s) - 1
    while l < r:
        while l < r and not s[l].isalnum():
            l += 1
        while l < r and not s[r].isalnum():
            r -= 1
        if s[l].lower() != s[r].lower():
            return False
        l += 1
        r -= 1
    return True
test:

q: Write `is_anagram(a, b)` without Counter, using a 26-slot list (lowercase letters only).
answer:
def is_anagram(a, b):
    if len(a) != len(b):
        return False
    count = [0] * 26
    for x, y in zip(a, b):
        count[ord(x) - ord("a")] += 1
        count[ord(y) - ord("a")] -= 1
    return all(c == 0 for c in count)

## module: g6 | Dry runs and debugging
summary: Find and fix the classic beginner bugs by tracing. Then the checkpoint that tells you you're ready for the Warm-up 50.
=== en
### Most bugs are one of ten
1. Off-by-one in `range` (missing the last item, or going one past the end).
2. Forgetting to update the loop variable in a `while` → infinite loop.
3. Wrong starting value for an accumulator (product starting at 0, max starting at 0 with negatives).
4. `return` inside the loop too early (returns after checking only the first item).
5. Updating variables in the wrong order (losing an old value).
6. Using `=` where you meant `==`, or `/` where you meant `//`.
7. Changing a list while looping over it.
8. Aliasing: two names for one list, or shared rows in a grid.
9. Not handling the empty input or a single item.
10. Mixing up index and value (`for x in nums` gives values, not indexes).

### The debugging drill
For each broken function below: **read it, predict what it returns for the given example, find the line that's wrong, then fix it.** Do it on paper first. The answer shows the fix.
