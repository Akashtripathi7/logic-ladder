## module: py11 | Tuples and sets
summary: Tuples (fixed groups, unpacking, multiple return values) and sets (unique items, O(1) membership, set maths).
=== en
### Tuples: a fixed group of values
```python
point = (3, 4)
x, y = point            # unpacking
print(point[0])         # 3
point[0] = 9            # TypeError: tuples are immutable
```
Use a tuple when a few values belong together and shouldn't change: a coordinate `(r, c)`, a pair `(value, index)`, an edge `(u, v, weight)`.

> **Analogy:** A tuple is a sealed envelope with a few items inside. You can read them, but you can't swap them without making a new envelope.

Tuples are everywhere in Python, often without brackets:
```python
a, b = b, a                 # packing and unpacking in one line
def min_max(nums):
    return min(nums), max(nums)   # returns ONE tuple
lo, hi = min_max([4, 1, 9])
for i, x in enumerate(nums):      # enumerate yields (i, x) tuples
```
A one-item tuple needs a comma: `(5,)`. `(5)` is just the number 5.

Because tuples can't change, they can be **dictionary keys and set items**, while lists can't. That's how we store visited grid cells: `seen.add((r, c))`.

### Sets: unique items, instant lookup
```python
guests = {"Riya", "Sam"}
guests.add("Riya")        # ignored, already there
guests.add("Zoya")
print(len(guests))        # 3
print("Sam" in guests)    # True, in O(1) on average
guests.remove("Sam")      # KeyError if missing
guests.discard("Nobody")  # no error if missing
empty = set()             # NOT {} (that's an empty dict)
```

> **Analogy:** A party guest list with a bouncer. Each name appears once. And checking "is this person on the list?" is instant, because the list is organised like a library index (hashing, see Video 1 and the Arrays & Hashing topic).

### Why sets matter in DSA
`x in some_list` scans every item: O(n). `x in some_set` jumps straight to where x would be: O(1) on average. Replacing a list with a set often turns an O(n²) solution into O(n):
```python
def has_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False
```

### Set maths
```python
a = {1, 2, 3, 4}
b = {3, 4, 5}
a | b    # union        {1, 2, 3, 4, 5}
a & b    # intersection {3, 4}
a - b    # difference   {1, 2}
a ^ b    # symmetric difference {1, 2, 5}
```
`set(nums)` removes duplicates in one step, and `len(set(nums)) != len(nums)` is a one-line duplicate check.

### Rules for sets
- **Unordered:** never rely on the printing order.
- Items must be **hashable** (immutable): numbers, strings, tuples. Not lists.
- `frozenset` is an immutable set (can be a dict key).

## module: py12 | Dictionaries
summary: Key → value maps, safe lookups with get, looping, the counting and grouping patterns, defaultdict and Counter.
=== en
### A dictionary maps keys to values
```python
stock = {"apple": 5, "mango": 2}
print(stock["apple"])      # 5
stock["kiwi"] = 7          # add a new key
stock["mango"] += 1        # update → 3
del stock["apple"]         # remove
print(len(stock), "kiwi" in stock)   # 2 True
```

> **Analogy:** Your phone's contact list. You look someone up by **name** (the key) and get their **number** (the value). You never search contact #37; you search "Riya". And lookup is instant, just like sets (hashing).

### Missing keys
```python
stock["pear"]              # KeyError!
stock.get("pear")          # None (no error)
stock.get("pear", 0)       # 0  (your default)
```
`get(key, default)` is the safe way to read.

### Looping over a dictionary
```python
for key in stock:                 # keys
for value in stock.values():      # values
for key, value in stock.items():  # both (most useful)
    print(key, value)
```
Dictionaries remember **insertion order** (Python 3.7+).

### Pattern 1: counting
The single most used pattern in DSA 150:
```python
count = {}
for ch in "banana":
    count[ch] = count.get(ch, 0) + 1
print(count)    # {'b': 1, 'a': 3, 'n': 2}
```
Read the key line slowly: *old count, or 0 if missing, plus one*.

### Pattern 2: remembering where you saw something
```python
seen = {}                     # value → index
for i, x in enumerate(nums):
    need = target - x
    if need in seen:
        return [seen[need], i]
    seen[x] = i
```
That is the whole of Two Sum.

### Pattern 3: grouping
```python
groups = {}
for w in ["eat", "tea", "tan", "ate"]:
    key = "".join(sorted(w))          # "aet"
    groups.setdefault(key, []).append(w)
# {'aet': ['eat', 'tea', 'ate'], 'ant': ['tan']}
```

### defaultdict and Counter (from collections)
They remove the boilerplate:
```python
from collections import defaultdict, Counter

groups = defaultdict(list)     # missing keys start as []
groups["aet"].append("eat")

count = defaultdict(int)       # missing keys start as 0
count["a"] += 1

c = Counter("banana")          # {'a': 3, 'n': 2, 'b': 1}
c.most_common(1)               # [('a', 3)]
Counter("listen") == Counter("silent")   # True: an anagram check!
```

### Keys must be hashable
Keys can be numbers, strings or tuples, not lists. For a grid cell use `(r, c)`.

### Dictionary comprehension
```python
squares = {x: x * x for x in range(5)}   # {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
```

### Costs
`d[key]`, `d[key] = v`, `key in d`, `del d[key]` are all O(1) on average. Looping over all items is O(n).

## module: py13 | Functions
summary: Defining functions, parameters vs arguments, return, defaults, keyword args, *args, scope, lambda and passing functions around.
=== en
### A function is a machine
```python
def square(x):
    return x * x

print(square(4))    # 16
print(square(9))    # 81
```
> **Analogy:** A juicer. Put oranges in (the **input**), it does its job, and juice comes out (the **output**). Build it once, use it forever.

- `def` starts a function, then its name and **parameters** in brackets, then a colon.
- The indented body runs only when the function is **called**: `square(4)`.
- `4` is an **argument**: the actual value passed in. `x` is the parameter that receives it.
- `return` sends a value back **and ends the function immediately**.

### No return means None
```python
def greet(name):
    print("Hi", name)

result = greet("Riya")   # prints Hi Riya
print(result)            # None
```
Printing and returning are different! `print` shows something to a human; `return` hands a value back to the code that called the function. LeetCode checks what you **return**.

### Returning several values
```python
def min_max(nums):
    return min(nums), max(nums)   # a tuple
lo, hi = min_max([3, 9, 1])
```

### Default and keyword arguments
```python
def power(base, exp=2):
    return base ** exp

power(5)            # 25 (exp defaults to 2)
power(2, 10)        # 1024
power(exp=3, base=2)   # 8, arguments by name
```
> **Mistake:** Never use a mutable default like `def f(items=[])`. The same list is shared by every call. Use `items=None` and create the list inside.

### *args and **kwargs
```python
def total(*nums):        # any number of positional args → a tuple
    return sum(nums)
total(1, 2, 3)           # 6

def show(**info):        # any keyword args → a dict
    print(info)
show(name="Riya", age=20)
```

### Scope: variables live in rooms
Variables created inside a function exist only inside it:
```python
def f():
    temp = 5
f()
print(temp)     # NameError
```
> **Analogy:** Each function call gets its own room. What happens in the room stays in the room. Two functions can both have a variable `i` without any clash.

A function **can read** variables from outside, but to **reassign** an outer variable you'd need `global` / `nonlocal`. In DSA we often use nested helper functions that update an outer result; `nonlocal` or a list/`self` attribute handles that:
```python
def diameter(root):
    best = 0
    def height(node):
        nonlocal best
        ...
```

### Functions are values
You can pass a function to another function. This is how custom sorting works:
```python
words = ["banana", "kiwi", "apple"]
sorted(words, key=len)                  # ['kiwi', 'apple', 'banana']
sorted(words, key=lambda w: w[-1])      # sort by last letter
```
`lambda args: expression` is a tiny unnamed function.

### Type hints (you'll see them on LeetCode)
```python
def two_sum(nums: List[int], target: int) -> List[int]:
```
They're labels for humans and tools. Python doesn't enforce them.

### How to design a function
1. Name what it does (`is_prime`, `count_vowels`).
2. Decide inputs and output.
3. Handle edge cases first (empty input, 0, 1).
4. Write the main logic.
5. Test with small examples.

## module: py14 | Recursion
summary: Functions that call themselves: base case, recursive case, the call stack, memoization and when to use it.
=== en
### What is recursion?
A function that calls **itself** on a **smaller** version of the same problem.

> **Analogy:** Russian dolls. Open a doll, and there's a smaller doll inside. Keep opening until you reach the tiny doll that doesn't open. That tiny doll is the **base case**.

```python
def fact(n):
    if n == 1:            # base case: the tiny doll
        return 1
    return n * fact(n - 1)   # recursive case: a smaller doll
```

### Two parts, always
1. **Base case**: the smallest input you can answer directly. Without it, the calls never stop → `RecursionError: maximum recursion depth exceeded`.
2. **Recursive case**: call yourself on a smaller input, and combine the answer.

### The call stack
`fact(4)` can't finish until `fact(3)` finishes, which waits for `fact(2)`, which waits for `fact(1)`:
```
fact(4) waits: 4 × fact(3)
  fact(3) waits: 3 × fact(2)
    fact(2) waits: 2 × fact(1)
      fact(1) = 1          ← base case
    fact(2) = 2
  fact(3) = 6
fact(4) = 24
```
The waiting calls pile up like plates on a **stack**, then come off one by one.

### Trust the smaller call
The mental trick: **don't trace every level**. Assume `fact(n - 1)` already returns the right answer, and ask only: "how do I use it to get fact(n)?" This "leap of faith" is how you design recursive solutions for trees and backtracking.

### More examples
```python
def total(nums):                 # sum of a list
    if not nums:
        return 0
    return nums[0] + total(nums[1:])

def power(x, n):                 # x^n in O(log n)
    if n == 0:
        return 1
    half = power(x, n // 2)
    return half * half if n % 2 == 0 else half * half * x

def count_down(n):
    if n == 0:
        print("Go!")
        return
    print(n)
    count_down(n - 1)
```

### Repeated work and memoization
```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```
`fib(40)` makes over 300 million calls, because `fib(38)`, `fib(37)`… are recomputed again and again. Fix: remember answers.
```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```
Now each `fib(k)` is computed once: O(n). This is the heart of **dynamic programming**.

### Limits
Python allows about 1000 nested calls by default. Deep recursion (like a DFS over a 10⁵-node chain) can crash; you can raise the limit with `sys.setrecursionlimit(10**6)` or rewrite with an explicit stack.

### When to use recursion
When a problem is naturally made of smaller copies of itself: trees, backtracking (subsets, permutations), divide and conquer (merge sort, binary search), and DP.

### Recursion kya hai?
Aisa function jo **khud ko** call kare, usi problem ke **chhote** version pe.

> **Analogy:** Russian dolls. Ek doll kholo, andar chhoti doll. Kholte raho jab tak wo chhoti si doll na aa jaaye jo khulti nahi. Wahi chhoti doll **base case** hai.

### Hamesha do hisse
1. **Base case**: sabse chhota input jiska answer seedha pata hai. Iske bina calls kabhi nahi rukengi → `RecursionError`.
2. **Recursive case**: chhote input pe khud ko call karo aur answer jodo.

### Call stack
`fact(4)` tab tak khatam nahi hota jab tak `fact(3)` khatam na ho, jo `fact(2)` ka wait karta hai… `fact(1) = 1` base case pe pahunchke plates ek-ek karke utarti hain: 2, 6, 24. Wait karne wali calls **stack** ki plates jaisi jama hoti hain.

### Chhoti call pe bharosa karo
Trick: **har level trace mat karo**. Maan lo `fact(n - 1)` sahi answer deta hai, aur sirf itna socho: "isse fact(n) kaise banaun?" Trees aur backtracking mein recursive solution aise hi design hote hain.

### Repeated work aur memoization
Seedha `fib(n) = fib(n-1) + fib(n-2)` likhoge toh `fib(40)` 30 crore se zyada calls karega, kyunki same values baar-baar calculate hoti hain. Hal: answers yaad rakho. `@lru_cache(maxsize=None)` lagao, har `fib(k)` ek hi baar banega: O(n). Yahi **dynamic programming** ka dil hai.

### Limit
Python by default lagbhag 1000 nested calls allow karta hai. Bahut gehri recursion crash kar sakti hai; `sys.setrecursionlimit(10**6)` se limit badha sakte ho ya explicit stack se likho.

### Recursion kab use karein
Jab problem apne hi chhote copies se bani ho: trees, backtracking (subsets, permutations), divide and conquer (merge sort, binary search) aur DP.

def power(x, n):

    return half * half * x

## module: py15 | Built-in tools you'll use every day
summary: len, sum, min/max with key, sorted, enumerate, zip, reversed, any/all, map/filter, divmod, abs and unpacking tricks.
=== en
Python ships with a toolbox that turns 5-line loops into one readable line. Learn these; interviewers love clean Python.

### Measuring and summarising
```python
nums = [4, -2, 9, 1]
len(nums), sum(nums), min(nums), max(nums)   # 4, 12, -2, 9
max(["kiwi", "banana"], key=len)             # 'banana'
min(points, key=lambda p: p[0]**2 + p[1]**2) # closest point
abs(-7), round(3.567, 2), divmod(17, 5)      # 7, 3.57, (3, 2)
```

### Sorting
```python
sorted(nums)                         # new list, ascending
sorted(nums, reverse=True)           # descending
sorted(words, key=len)               # by a computed key
sorted(pairs, key=lambda p: (p[1], p[0]))   # by second, then first
intervals.sort(key=lambda iv: iv[0]) # in place, by start
```
Sorting is **stable**: equal items keep their original order. Cost: O(n log n).

### enumerate and zip
```python
for i, x in enumerate(nums):          # index + value
for i, x in enumerate(nums, start=1): # count from 1
for a, b in zip(list1, list2):        # walk two lists together
    ...
pairs = list(zip([1, 2, 3], "abc"))   # [(1,'a'), (2,'b'), (3,'c')]
```
`zip` stops at the shorter list.

### reversed, any, all
```python
for x in reversed(nums): ...          # walk backwards (no copy)
any(x < 0 for x in nums)              # True if at least one is negative
all(x > 0 for x in nums)              # True if every one is positive
```

### map and filter
```python
list(map(int, "3 5 7".split()))              # [3, 5, 7]
list(filter(lambda x: x % 2 == 0, nums))     # evens
```
A list comprehension (`[int(s) for s in parts]`) often reads better.

### Unpacking tricks
```python
first, *rest = [1, 2, 3, 4]     # first = 1, rest = [2, 3, 4]
*init, last = [1, 2, 3, 4]      # last = 4
a, b = b, a                     # swap
r, c = divmod(k, cols)          # index k → (row, col) in a grid
```

### Infinity and big numbers
```python
best = float("inf")        # bigger than any number
worst = float("-inf")
```
Use them as starting values for min/max searches.

### Strings ↔ lists
```python
list("abc")            # ['a', 'b', 'c']
"".join(['a', 'b'])    # 'ab'
" ".join(map(str, [1, 2, 3]))   # '1 2 3'
```

> **Tip:** Knowing these makes your code shorter, but in interviews always be able to explain what the built-in costs. `max(nums)` is still an O(n) loop inside.

## module: py16 | Comprehensions and Pythonic style
summary: List, set and dict comprehensions, conditions inside them, nested comprehensions for grids, generator expressions and writing readable Python.
=== en
### List comprehension = a loop that builds a list
Instead of:
```python
squares = []
for x in range(6):
    squares.append(x * x)
```
write:
```python
squares = [x * x for x in range(6)]    # [0, 1, 4, 9, 16, 25]
```
Read it as: **[what to keep  for each item  in where]**.

> **Analogy:** A factory conveyor belt. Items come in from the right (`for x in ...`), an optional inspector throws some away (`if ...`), and a machine shapes each survivor (the expression on the left).

### With a filter
```python
evens = [x for x in nums if x % 2 == 0]
words = [w.lower() for w in text.split() if w.isalpha()]
```

### With if/else (transforming, not filtering)
```python
labels = ["even" if x % 2 == 0 else "odd" for x in nums]
```
Note the position: a filter `if` goes at the **end**; a value-choosing `if/else` goes at the **front**.

### Set and dict comprehensions
```python
unique_lengths = {len(w) for w in words}
index_of = {x: i for i, x in enumerate(nums)}
```

### Nested comprehensions (grids)
```python
grid = [[0] * cols for _ in range(rows)]            # correct empty grid
flat = [x for row in grid for x in row]              # flatten
transposed = [[m[r][c] for r in range(len(m))] for c in range(len(m[0]))]
```
The `for` clauses read in the same order as nested loops.

### Generator expressions
Round brackets instead of square ones produce values **one at a time** without building a list:
```python
total = sum(x * x for x in range(1_000_000))   # no giant list in memory
has_neg = any(x < 0 for x in nums)             # stops at the first negative
```

### Pythonic habits interviewers like
- Swap with `a, b = b, a`.
- `for x in nums` instead of `for i in range(len(nums))` when you don't need i.
- `if not stack:` instead of `if len(stack) == 0:`.
- Chained comparisons: `if 0 <= r < rows and 0 <= c < cols:`.
- `"".join(parts)` to build strings.
- `float("inf")` as a starting minimum.
- Clear names: `left, right`, `seen`, `count`, `best`.

> **Remember:** Comprehensions are for simple transformations. If you need several steps, `break`, or complex logic, a normal loop is clearer. Readable beats clever.
