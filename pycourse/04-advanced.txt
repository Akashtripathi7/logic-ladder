## module: py17 | Classes and objects
summary: Blueprints and objects, __init__ and self, methods, __repr__, comparisons for heaps, and why ListNode/TreeNode are classes.
=== en
### Blueprint and objects
A **class** is a blueprint. An **object** (instance) is a thing built from it.

> **Analogy:** An architect's plan for a house is the class. Every actual house built from that plan is an object. All houses share the design, but each has its own paint colour and owner.

```python
class Student:
    def __init__(self, name, marks):
        self.name = name        # attributes: data stored on THIS object
        self.marks = marks

    def passed(self):           # a method: a function that belongs to the object
        return self.marks >= 40

s = Student("Riya", 82)
print(s.name, s.passed())       # Riya True
t = Student("Sam", 30)
print(t.passed())               # False
```

### __init__ and self
- `__init__` runs automatically when you create an object: `Student("Riya", 82)`.
- `self` is **the object itself**. `self.name = name` means "store name on this particular student".
- Every method's first parameter is `self`. Python passes it for you: `s.passed()` is really `Student.passed(s)`.

### Changing state
```python
class Counter:
    def __init__(self):
        self.count = 0
    def click(self):
        self.count += 1

c = Counter()
c.click(); c.click()
print(c.count)    # 2
```
Each object keeps its own state. This is how "design" problems work: `MinStack`, `LRUCache`, `Trie`, `MedianFinder` are all classes that keep data between method calls.

### Printing objects: __repr__
```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Point({self.x}, {self.y})"
print(Point(2, 3))    # Point(2, 3) instead of <__main__.Point object at 0x…>
```

### Comparing objects (needed for heaps)
`heapq` needs to compare items. Tuples compare element by element, so the usual trick is to push `(priority, tie_breaker, item)`. Or define `__lt__`:
```python
class Task:
    def __init__(self, prio, name):
        self.prio, self.name = prio, name
    def __lt__(self, other):
        return self.prio < other.prio
```

### Linked lists and trees are tiny classes
```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next         # another ListNode, or None at the end

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right
```
LeetCode gives you these definitions at the top of the problem. A linked list is objects pointing to each other: `ListNode(1, ListNode(2, ListNode(3)))`.

### Inheritance (a quick look)
```python
class Animal:
    def speak(self): return "..."
class Dog(Animal):
    def speak(self): return "Woof"
```
`Dog` gets everything `Animal` has and can override it. Useful to know; rarely needed in DSA.

> **Remember:** Attributes are nouns (what an object HAS); methods are verbs (what it DOES).

answer:
class Stack:
    def __init__(self):
        self.items = []
    def push(self, x):
        self.items.append(x)
    def pop(self):
        return self.items.pop()
    def peek(self):

    def is_empty(self):

## module: py18 | Errors, exceptions and debugging
summary: Reading tracebacks, the common exceptions, try/except/finally, raise, assert, and a calm debugging process.
=== en
### Two kinds of errors
- **SyntaxError / IndentationError**: Python can't even understand the code (missing colon, bracket, wrong indentation). Nothing runs.
- **Exceptions**: the code is valid but something goes wrong while running, like dividing by zero.

### Reading a traceback
```
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    print(total(nums))
  File "main.py", line 2, in total
    return nums[0] + nums[5]
IndexError: list index out of range
```
Read from the **bottom**: the last line is *what* happened (IndexError), and the lines above show *where* (line 2, inside `total`, called from line 4).

### The exceptions you'll meet most
| Exception | Usually means | Example |
|---|---|---|
| `IndexError` | index outside the list/string | `nums[len(nums)]` |
| `KeyError` | dict key doesn't exist | `d["missing"]` |
| `TypeError` | wrong type for the operation | `"5" + 5` |
| `ValueError` | right type, bad value | `int("abc")` |
| `ZeroDivisionError` | dividing by 0 | `10 / 0` |
| `NameError` | variable not defined (typo?) | `pritn(x)` |
| `AttributeError` | object has no such attribute | `None.val` |
| `RecursionError` | recursion too deep / no base case | |

`AttributeError: 'NoneType' object has no attribute 'val'` is the classic linked-list/tree bug: you used `node.val` when `node` was `None`. Always check `if node:` first.

### Handling exceptions
```python
try:
    n = int(text)
except ValueError:
    print("Not a number")
else:
    print("Parsed", n)       # runs only if no exception
finally:
    print("Done")            # always runs
```
Raise your own:
```python
def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("Insufficient balance")
    return balance - amount
```
`assert condition, "message"` crashes if the condition is false: a quick self-check while developing.

> **Tip:** In DSA code you rarely need try/except. Prefer preventing errors: check bounds (`0 <= r < rows`), use `dict.get`, and check `if node`.

### A calm debugging process
1. **Read the error**, bottom line first. Which line? Which variable?
2. **Reproduce with the smallest input** that fails (empty list, one item, two items).
3. **Print the state** inside the loop: `print(i, l, r, nums)`. Seeing beats guessing.
4. **Trace by hand** with a table, and compare with what the prints show. The first row where they differ is your bug.
5. **Check the usual suspects**: off-by-one in range, `=` vs `==`, forgot to update the loop variable, returning inside the loop too early, modifying a list while looping, shared 2-D rows, integer vs float division.
6. **Rubber duck**: explain your code line by line out loud. You'll often hear the bug yourself.

## module: py19 | Modules and the DSA standard library
summary: import, and the tools DSA 150 solutions rely on: math, collections (deque, Counter, defaultdict), heapq, bisect, itertools and functools.
=== en
### Importing
```python
import math
from collections import deque, Counter, defaultdict
import heapq
```
A **module** is a file of ready-made code. Python's standard library is huge; these are the parts DSA uses constantly.

### math
```python
math.sqrt(16)      # 4.0
math.isqrt(17)     # 4  (integer square root)
math.gcd(48, 18)   # 6
math.ceil(4.1), math.floor(4.9)   # 5, 4
math.inf           # same as float("inf")
math.log2(1024)    # 10.0
```

### collections.deque: a fast queue
A list's `pop(0)` is O(n). A **deque** (double-ended queue) adds and removes at **both** ends in O(1).
```python
q = deque([1, 2])
q.append(3)        # right end
q.appendleft(0)    # left end
q.popleft()        # 0  ← use for BFS queues
q.pop()            # 3
```
> **Analogy:** A queue at a ticket counter with doors at both ends.

### collections.Counter and defaultdict
Covered in module 12: `Counter(iterable)` counts things; `defaultdict(list/int/set)` gives missing keys a starting value.

### heapq: priority queues
Python's heap is a **min-heap** stored in a normal list: the smallest item is always at index 0.
```python
h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
heapq.heappop(h)      # 1 (smallest)
h[0]                  # 3 (peek)
heapq.heapify(nums)   # turn a list into a heap in O(n)
heapq.nlargest(2, nums), heapq.nsmallest(2, nums)
```
**Max-heap trick:** push negatives: `heappush(h, -x)`, and negate when popping.
Tuples compare element by element, so `heappush(h, (distance, node))` orders by distance.

### bisect: binary search on sorted lists
```python
import bisect
a = [1, 3, 3, 7]
bisect.bisect_left(a, 3)    # 1: first position where 3 could go
bisect.bisect_right(a, 3)   # 3: position after the last 3
bisect.insort(a, 5)         # insert keeping it sorted
```

### itertools
```python
from itertools import permutations, combinations, product, accumulate
list(permutations([1, 2, 3]))      # all 6 orderings
list(combinations([1, 2, 3], 2))   # (1,2) (1,3) (2,3)
list(accumulate([1, 2, 3, 4]))     # [1, 3, 6, 10] prefix sums
```
Great for checking your answers. In interviews you're usually asked to write backtracking yourself.

### functools: caching
```python
from functools import lru_cache, cache
@cache                    # Python 3.9+; same as lru_cache(maxsize=None)
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)
```
Memoization in one line. Top-down DP becomes trivial.

### Costs cheat sheet
| Tool | Operation | Cost |
|---|---|---|
| deque | append/appendleft/pop/popleft | O(1) |
| heapq | push / pop | O(log n) |
| heapq | peek `h[0]`, heapify | O(1), O(n) |
| bisect | bisect_left/right | O(log n) |
| bisect | insort | O(n) (shifting) |
| Counter | build from n items | O(n) |

## module: py20 | Iterators, generators, files and packages
summary: How for loops really work, generators with yield, reading/writing files with `with`, and installing packages with pip.
=== en
### How a for loop really works
Any object you can loop over is **iterable** (lists, strings, dicts, ranges, files). A for loop asks it for an **iterator** and calls `next()` until it runs out:
```python
it = iter([10, 20])
next(it)    # 10
next(it)    # 20
next(it)    # StopIteration: the for loop catches this and stops
```

### Generators: values on demand
A function with `yield` becomes a **generator**. It pauses at each `yield` and resumes on the next request:
```python
def count_up(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for x in count_up(3):
    print(x)     # 1 2 3
```
> **Analogy:** A list is a fully cooked buffet: everything is made in advance and takes space. A generator is a chef who cooks one dish at a time, only when you ask. Great for huge or endless sequences.

`range` works like this too, which is why `range(10**9)` doesn't use gigabytes of memory.

### Reading and writing files
```python
with open("notes.txt", "w") as f:       # "w" = write (overwrites)
    f.write("line one\n")
    f.write("line two\n")

with open("notes.txt") as f:            # default "r" = read
    for line in f:
        print(line.strip())
```
`with` closes the file automatically, even if an error happens. Modes: `"r"` read, `"w"` write, `"a"` append.

### Packages with pip
The standard library is big, but the world has more: `pip install requests` installs a package from PyPI. Use a **virtual environment** per project so packages don't clash:
```
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install requests
```
For DSA practice you won't need any third-party packages.

### if __name__ == "__main__":
```python
def solve():
    ...
if __name__ == "__main__":
    solve()
```
Code under this line runs when you execute the file directly, but not when another file imports it. A tidy habit for practice scripts.

### Decorators (a peek)
`@cache` above a function is a **decorator**: a function that wraps another function to add behaviour (here: remembering results). You only need to *use* them for DSA.

## module: py21 | Python for DSA: costs and gotchas
summary: How fast Python is, what each operation costs, and the traps that catch people in interviews.
=== en
### How fast is Python?
Python does roughly **10 to 50 million simple operations per second**: slower than C++ or Java, but LeetCode's time limits are set with this in mind. Rule of thumb:
| n up to | aim for |
|---|---|
| 10–20 | O(2ⁿ), O(n!) (backtracking) |
| 1,000 | O(n²) |
| 100,000 | O(n log n) or O(n) |
| 10⁹ | O(log n) or O(1) |

### The costs table (keep it next to you)
| Operation | Cost |
|---|---|
| `list[i]`, `append`, `pop()` | O(1) |
| `list.insert(0, x)`, `pop(0)` | O(n) → use `deque` |
| `x in list`, `list.index`, `remove` | O(n) → use a `set`/`dict` |
| `x in set`, `x in dict`, `d[k]` | O(1) average |
| `sorted`, `list.sort` | O(n log n) |
| slicing `a[i:j]`, `a[::-1]` | O(j − i): it copies! |
| `s + t` for strings | O(len(s) + len(t)) → collect in a list and `"".join` |
| `heappush`, `heappop` | O(log n) |
| `len(x)` | O(1) |
| `min`, `max`, `sum`, `count` | O(n) |

### Gotchas that cost people interviews
1. **Shared rows:** `[[0] * c] * r` shares one row. Use `[[0] * c for _ in range(r)]`.
2. **Mutable defaults:** `def f(path=[])` shares the list between calls.
3. **Aliasing:** `res.append(path)` in backtracking appends the SAME list that you keep changing. Append a copy: `res.append(path[:])` or `path.copy()`.
4. **Slicing in recursion:** `f(nums[1:])` copies the list on every call → O(n²). Pass an index instead.
5. **String building in a loop:** `s += ch` repeatedly can be O(n²). Use a list and `join`.
6. **Integer division with negatives:** `-7 // 2 == -4`. For "truncate toward zero" use `int(a / b)`.
7. **Recursion depth:** default limit ~1000. Deep DFS may need `sys.setrecursionlimit` or an iterative version.
8. **Modifying while iterating:** don't add/remove items of a list, set or dict you are looping over.
9. **`is` vs `==`:** use `==` for values, `is` only for `None`.
10. **Sorting with a key:** `sort()` returns None; `sorted()` returns a list.

### LeetCode-style Python
LeetCode wraps your function in a class:
```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, x in enumerate(nums):
            if target - x in seen:
                return [seen[target - x], i]
            seen[x] = i
```
Our solutions are written as plain functions so they're easy to read and run anywhere. To submit on LeetCode, paste the body inside the method and add `self` where needed.
